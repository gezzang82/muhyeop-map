- 협찬 리뷰어(블로거) 직접 활동 중. 와이프도 협찬 활동.
- 터미널/git 기초 수준. VS Code 미설치.
- 아이디어 발굴력 좋음 — 본인이 겪은 불편함에서 직접 서비스 기획.

## 작업 스타일

- 코드보다 **결과물 중심** — 코드 설명 불필요, 기능 동작 확인 선호.
- 기능 레이아웃 확정 후 **피그마로 직접 디자인** 예정. 지금은 기능 우선.
- 한 번에 여러 수정사항을 몰아서 요청하는 편.
- 중요한 판단은 직접 내림 (예: 신청하기 버튼 제거, Phase 구분 등).

## 제품 감각 (무협맵 관련 직접 언급한 인사이트)

- **핵심 사용 패턴**: 리뷰어는 "내 위치 기준"이 아니라 "협찬 당첨 위치 기준"으로 주변 협찬을 찾음. 강남 협찬 하나 당첨되면 무협맵에서 강남 검색 → 주변 협찬 추가 신청 → 하루 루트 묶기.
- **신청 링크 문제 인지**: 플랫폼 URL은 로그인 필요 케이스 많음 → 일단 버튼 제거, Phase 2에 화이트리스트로 재도입.
- **악의적 등록 우려**: 누군가 협찬 링크 대신 자기 블로그 URL 넣는 케이스 → 신고 기능 + 화이트리스트로 해결 예정.
- 보통 협찬은 종료 후 재오픈되는 경우 많음 → 반복 캠페인 구조 고려 필요.
- Firebase, 간편 로그인(카카오/네이버) 등 기술 용어 이해하고 있음. 시점 조율은 본인이 판단.
