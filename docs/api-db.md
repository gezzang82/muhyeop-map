# API / 데이터베이스

## 구성
- Vercel 서버리스 함수 (`api/*.js`) + Turso(libSQL) — `api/_db.js`의 `getDb()`로 클라이언트 생성 (`TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` 환경변수 필요)
- `schema.sql`: 테이블 정의 원본. 실제 운영 DB 스키마 변경은 각 API 핸들러 내 `ALTER TABLE ... ADD COLUMN` try/catch 패턴으로 점진 적용되는 경우가 있음 (예: `campaigns.js`의 `source` 컬럼)
- **환경변수**: 위 Turso 2개 + `SESSION_SECRET`·`ADMIN_PASSWORD`·`PUBLIC_BASE_URL`·카카오/네이버 OAuth·`NAVER_SEARCH_*`. **오토파일럿용 추가**: `OPENAI_API_KEY`(AI 판정), 선택 `OPENAI_MODEL`(기본 gpt-4o-mini). (`CRON_SECRET`은 크론 폐지 2026-08-30로 불필요 — 수동 autopilot은 관리자 인증만으로 접근) **지오코딩(2026-08-30)**: `NAVER_MAPS_KEY_ID`/`NAVER_MAPS_KEY`(네이버 NCP Geocoding, 주소→좌표. 지도 스크립트 ncpKeyId와 동일 NCP 계정 — 로컬·Vercel 양쪽 등록 필요).
- **⚠️ Sensitive 변수와 `.env.local`**: 카카오/네이버 OAuth·`ADMIN_PASSWORD`·`SESSION_SECRET` 등은 Vercel에서 Sensitive라 `vercel env pull`로 **빈 값으로 내려와 로컬 파일을 덮어씀**(사고 이력). `.env.local` 수정은 [[15-operations]] 8절의 보호 훅(`.claude/hooks/protect-env-local.sh`)이 차단하므로, 값 추가는 각 콘솔에서 직접 복사해 넣는다.
- **수집 실행**: **로컬 크롤러(`scripts/crawl-worker.js`)로 단일화**(Vercel 크론 폐지 2026-08-30). 컴퓨터가 켜진 동안 전 플랫폼을 순회 수집→오토파일럿(무제한 반복). 수동 오토파일럿은 어드민 버튼(`POST ?action=autopilot`, 관리자 인증). `functions.maxDuration=300`은 그 수동 엔드포인트 시간예산으로 유지. **왜 크론 폐지**: 크론은 디너의여왕만 커버 + 06:00에 컴퓨터 켜져 있으면 로컬 크롤러와 오토파일럿이 겹쳐 중복매장 생성 위험. 상세 `docs/product/03-platform-analysis.md` 8절.

## 엔드포인트
- `api/places.js` — 장소 CRUD. **공개 GET은 숨김 매장 제외 + `founderEmail`(PII) 제거**, `?admin=1` 서버사이드 조회는 `requireAdmin`(이메일 포함). **지도 경량화 v2(2026-09-11)**: 공개 GET에 `?map=1`(지도 마커용 — **활성 캠페인 OR 후기 있는 매장만**, ~20.7k, `hasReview` 플래그, 엣지캐시)·`?q=이름`(전체 비숨김 매장 서버검색, 공백무시, 죽은 매장도 후기 등록 위해 찾음) 분기 추가. 파라미터 없는 전량 GET은 어드민·폴백용 유지. 상세 [[frontend]] 지도 경량화 v2. 제보 POST에 레이트리밋(IP당 1분 15회), 이메일은 로그인 사용자만 `userId`로 `users`에서 조회해 저장(비로그인 미수집). 후기(리뷰) 라우팅도 합쳐짐(`?reviews=`). **사이트 방문 집계도 합쳐짐(`?visit=`)**: 공개 페이지 로드 시 `POST ?visit=1`(app.js `loadInitialData`에서 fire-and-forget)로 `site_daily`에 PV +1 / `site_visitor`(IP+KST일자 PK)로 UV 중복제거 후 +1(fail-open), `GET ?visit=stats`(requireAdmin)는 오늘·누적 PV/UV + 최근 7일 반환(어드민 대시보드 방문 카드). **체류시간·일별 유입경로 추가(2026-09-09)**: `?visit=1`이 `site_referrer_daily`(일자×채널)에도 누적, **`POST ?visit=dwell`**(공개 페이지 이탈 시 클라가 `visibilitychange hidden`/`pagehide`에 `navigator.sendBeacon`으로 머문 초 1회 전송, app.js)이 `site_daily.dwell_sum/dwell_count`에 누적(30분 상한, 평균=합/수). `?visit=stats`가 `todayDwell`·`todayReferrers`·`referrerDaily`(14일 날짜×채널)도 반환. **운영자 집 IP 집계 제외**: `EXCLUDED_VISIT_IPS`(기본 확인된 집IP, 환경변수 `EXCLUDED_VISIT_IPS` 콤마구분으로 추가) 매칭 시 `?visit=1`·`?visit=dwell`를 스킵({excluded:true}) — 자기 접속이 PV/UV/체류를 부풀리지 않게(단 사설망 IP는 서버에 도달 안 하니 공인 IP를 넣어야 함). **공개 GET 엣지 캐싱(2026-08-30)**: `Cache-Control: public, s-maxage=3600, stale-while-revalidate=7200` — 방문자마다 전체 매장 조회(~4초)하던 것을 CDN 히트로. 어드민(`?admin=1`)·쓰기·visit은 캐시 대상 아님. **채널 태그 정확추적(`?ref=`, 2026-09-15)**: 카톡·앱 인앱브라우저는 referrer 미전달이라 오픈채팅 유입이 `direct`에 뭉뚱그려짐 → 공유 링크에 `?ref=kakao`(`utm_source`도 인정) 붙이면 클라가 방문 핑 `src`로 전송(sessionStorage로 세션 유지), 서버 `normalizeSrc(src)`가 우선(별칭 kko/thread/insta/fb·소독)해 `site_referrer(_daily)`에 그 채널로 기록. **threads.com→'threads' 통합(2026-09-20)**: `classifyReferrer`가 host를 그대로 반환해 '스레드'와 '스레드.com'이 유입 카드에 따로 잡히던 것을 `host.includes('threads')`→`'threads'` + `normalizeSrc` 별칭 `threadscom→threads`로 한 채널로 병합. **`?reviews=recent&limit=N`(공개, 2026-09-15)**: 최근 후기(매장명·닉네임 조인, 숨김/숨김매장 제외, 엣지캐시) — 라이브버블(후기 등록 알림, [[frontend]])용.
- `api/campaigns.js` — 협찬 캠페인 CRUD + 조회/클릭수 트래킹(`POST ?track=view|click&id=`). `view_count`/`click_count` 컬럼에 누적하며 `campaign_events(campaign_id, kind, visitor_key, created_at)` UNIQUE로 **IP+일자 기준 중복 제거**(클라이언트는 세션당 view 1회 디바운스). **`GET ?clickstats=1`(관리자)**: `campaign_events`를 조인 집계해 `daily`(일별)·`regions`(시/도별)·`categories`·**`platforms`(플랫폼별 상세보기(view)/페이지이동(click), 오늘+누적, 2026-09-23)** 반환 → 어드민 클릭 카드 [[admin]]. 함수 12개 제한 때문에 별도 엔드포인트 분리 없이 campaigns.js에 합침. `PATCH`는 두 갈래: 바디에 `platform` 없이 `hidden`만 오면 **hidden 토글만(부분 업데이트)** 처리(신고 목록의 캠페인 숨김/노출용), 그 외엔 전체 필드 수정. **공개 GET은 숨김 캠페인 + 숨김 매장 소속 캠페인 제외 + `reporterEmail`(PII) 제거**, `?admin=1` 조회는 `requireAdmin`. **`?active=1`이면 만료(마감 지난) 캠페인도 제외**(KST 기준). **상시 만료(2026-09-23)**: 마감일 없는 '상시' 캠페인은 **등록 45일 이내만 활성**(`(deadline 빈값 AND created_at>=now-45일) OR deadline>=오늘`) — 오래된 상시가 영원히 뜨며 '협찬종료' 신고를 유발하던 tail 방지. 공개 활성필터 전부(count/recent/placeId/bbox/all)에 동일 적용. 어드민 대시보드는 통계용으로 전체(무필터)를 받음. **공개 앱 뷰포트 로딩(2026-09-01, 경량화)**: 공개 GET에 파라미터 분기 추가 — `?active=1&bbox=W,S,E,N`(bbox 안 매장의 활성 캠페인만, places 조인+`idx_places_lat_lng`, content 등 전체 필드), `?count=active`(전역 활성 수 `{count}`), `?recent=N`(최근 활성 N건+매장 name/lat/lng 조인, 라이브버블용), `?active=1&placeId=`(특정 매장 활성 캠페인, 상세 focus 폴백). 모두 엣지캐시. 공개 앱은 접속 시 캠페인 전량 대신 count/recent만 받고 지도 이동마다 bbox로 채움([[frontend]] 캠페인 뷰포트 로딩). 기존 `?active=1`(bbox 없음, 전량)은 어드민/폴백용 유지. 제보 POST 레이트리밋(1분 15회), 이메일은 로그인 사용자만 DB 조회 저장(비로그인 미수집). **과거 마감일 제보 차단(2026-09-18)**: 공개 제보 POST(`source!=='admin'`)에서 `deadline`이 오늘(KST)보다 과거면 400(이미 지난 캠페인 등록 방지, 클라 `submitCampaign`도 선검증 → [[frontend]]). **`?stats=1`에 후기 지표 추가(2026-09-20)**: `reviewCount`(전체 후기 수)·`reviewTodayCount`(오늘 등록, KST)를 반환(어드민 대시보드 후기 카드용, `reviews` 테이블 집계, try/catch). **데이터 수집 액션도 합쳐짐**(`?action=`, 함수 12개 제한): `scrape`(증분 수집→`scraped_items` 적재), `staged`/`runs`(조회), `review`/`bulkreview`/`editstaged`(승인·반려·수정) — 모두 `requireAdmin`. **`?action=autopilot`(AI 자동등록)**: 관리자 인증(requireAdmin) 또는 `Authorization: Bearer CRON_SECRET`(레거시, 현재 미사용), `?dry=1` 미리보기(쓰기 없음), `?scrape=dinnerqueen`이면 오토파일럿 후 수집도 실행. 실제 라우팅은 `_autopilot.js`. **평소 수집은 로컬 크롤러가 `runScrape`/`runAutopilot`를 직접 호출**(Vercel 크론 폐지 2026-08-30); 이 엔드포인트는 어드민 [지금 실행]/[미리보기] 버튼용. `campaigns.source`에 `'ai'`(자동등록)/`'admin'`(수집 승인)/`'user'`(유저 제보) 구분. **공개 GET 엣지 캐싱(2026-08-30)**: `?active=1` 등 공개 조회에 `Cache-Control: public, s-maxage=3600, stale-while-revalidate=7200`(활성 캠페인 1.2만 행 조회 ~6초 → CDN 히트 ~0.3초, 크롤 하루 단위 갱신이라 5분 지연 무해). 어드민·쓰기는 캐시 안 함.

  - `_admin.js`: **어드민 서버사이드 인증**(2026-06-29). `process.env.ADMIN_PASSWORD`(Vercel 환경변수, 필수)와 타이밍안전 비교 + SESSION_SECRET HMAC으로 어드민 쿠키(`mh_admin`) 발급/검증. `requireAdmin(req,res)`/`isAdmin(req)` 헬퍼. 어드민 로그인 = `POST /api/auth/login?admin=1 {password}`(login.js에 분기), 로그아웃은 logout.js가 어드민 쿠키도 정리. **게이트 적용**: `/api/users` 전체목록 GET, `campaigns`·`places`·`reports`의 PATCH/DELETE, `banners` 쓰기 = 관리자만. **공개 유지**: 제보(POST campaigns/places, places PATCH은 category 보정만)·신고(POST reports)·view/click 트래킹·`?leaderboard=1`·지도 GET. (과거 admin.js 하드코딩 `wonu1982`+무인증 갭 해소)
  - `_provider.js`: provider별 OAuth 설정(엔드포인트, clientId/secret, 프로필 파싱)을 모아둔 곳. 새 provider 추가 시 여기에 설정 객체만 추가. **현재 `parseProfile`이 수집하는 건 `providerUserId` + `nickname` + `email`뿐**(프로필 이미지·성별·나이 등은 수집/저장 안 함 — 개인정보 최소수집). 항목을 늘리려면 ① 카카오/네이버 콘솔의 동의항목(scope) 추가 ② `parseProfile`에 필드 추가 ③ `users` 테이블 컬럼 추가 ④ **개인정보처리방침(`policy/`) 갱신**이 한 세트로 필요
  - 세션 쿠키는 `HttpOnly; Secure; SameSite=Lax`. 로그인 사용자의 `reporter_nickname`/`founder_nickname`은 클라이언트 입력 대신 세션 닉네임을 우선 사용 (`api/campaigns.js`, `api/places.js`)

## 테이블 스키마 요약 (`schema.sql`)
- `users(id, provider, provider_user_id, nickname, email, url_platform, url_id, signup_source, created_at)` — 카카오/네이버/애플 로그인 사용자. `(provider, provider_user_id)` UNIQUE. `url_platform`/`url_id`는 프로필 설정 블로그/인스타 링크(제보·신고 폼 자동입력용). `signup_source`(2026-09-23)=가입 유입경로(네이버/카카오/스레드/app 등, 신규 가입 시 기록·소급불가, 위 `api/auth/` 참고)
- `places(id, name, address, lat, lng, category, founder_nickname, founder_email, founder_url, founder_user_id, created_at)`
- `campaigns(id, place_id, platform, channels, content, deadline, link, operating_days, operating_hours, exclude_holiday, reporter_nickname, reporter_email, reporter_blog, reporter_instagram, reporter_url, source, hidden, user_id, created_at)`
  - `deadline`은 빈 문자열 허용(마감일 없음), `source`는 등록 경로 구분: `'user'`(유저 제보)/`'admin'`(수집 승인)/`'ai'`(오토파일럿 자동등록)/`'unknown'`
  - `user_id`/`founder_user_id`는 로그인 사용자 식별용 nullable FK (`users.id`). 비로그인 제보도 계속 허용하므로 NULL 가능
  - **경쟁률/썸네일 공간(2026-09-19)**: `apply_count`(신청수)·`recruit_limit`(모집인원)·`thumbnail` 컬럼 추가(미사용 nullable, 나중에 채움). 포포몬/레뷰 목록에 경쟁률·썸네일이 있어 선반영해 둔 자리. `scraped_items`에도 동일 컬럼 존재
- `banners(id, image_url, link_url, start_date, end_date, hidden, sort_order, created_at)` — 이벤트 팝업. `sort_order`(2026-09-24)=노출 순서(작을수록 캐러셀 앞, 기본 맨 뒤)
- `reports(id, target_type, campaign_id, place_id, review_id, reason, detail, user_id, created_at)` — 신고 3종(`target_type`='place'|'campaign'|'review', 해당 id만 채움, 나머지 NULL). `user_id`는 로그인 사용자가 신고 시 세션에서 조용히 채워짐(입력 필드 없음). 비로그인 신고는 NULL. (기존 campaign_id NOT NULL 스키마에서 2026-07-02 재구성)
- `user_visits(user_id, visit_date)` — 로그인 사용자 접속 집계(1일 1회, `UNIQUE(user_id, visit_date)`). `me.js`가 로드 시 KST 날짜로 `INSERT OR IGNORE`. 어드민 회원 목록의 "접속수"에 사용
- `site_daily(visit_date PK, pv, uv, dwell_sum, dwell_count)` / `site_visitor(visit_date, visitor_key, PK(visit_date,visitor_key))` / `site_referrer(ref PK, cnt)` / `site_referrer_daily(visit_date, ref, cnt, PK(visit_date,ref))` — **전체 사이트 방문 집계**(비로그인 포함). `places.js ?visit=1`이 PV 누적 + IP 기준 UV 중복제거 + `document.referrer`를 `classifyReferrer`로 채널 분류해 `site_referrer`(누적)·`site_referrer_daily`(일자별, 2026-09-09) 누적. `dwell_sum`/`dwell_count`(2026-09-09)는 `?visit=dwell` beacon으로 체류시간 누적(평균=합/수, 30분 상한). 어드민 대시보드 "방문 카드/체류시간/추이 그래프(일·주·월)/유입경로(누적·일별)"(`?visit=stats[&period=]`). KST 일자 기준
- `scraped_items(id, platform, source_id, source_url, name, address, category, channel, content, deadline, hours, days, exclude_holiday, flags, dedupe_status, matched_place_id, status, created_campaign_id, auto_seen, auto_note, created_at, reviewed_at)` — **데이터 수집 스테이징(승인 대기 큐)**. `UNIQUE(platform, source_id)`+`INSERT OR IGNORE`로 멱등. `status`=pending|registered|rejected, `dedupe_status`=new_place|add_channel|renew|dup_active, `flags`=규칙 검증 경고. **오토파일럿 추적**: `auto_seen`(1=자동판정 완료, 재평가 안 함), `auto_note`(라우팅 사유, 검수큐 표시). `scrape_state(platform PK, last_max_id, last_run_at)`=증분 커서, `scrape_runs(...)`=수집/오토파일럿 실행 이력(`platform='autopilot'` 행 포함). 상세 `docs/product/03-platform-analysis.md`
- `push_tokens(id, user_id, device_id, platform, token UNIQUE, enabled, created_at, updated_at)` / `push_prefs(device_id, user_id, lat, lng, radius_km, categories, enabled, updated_at)` — 앱 푸시(FCM). `push_tokens`=기기별 FCM 토큰(`?push=register`, 같은 device_id 옛 토큰 `enabled=0`), `push_prefs`=관심위치(`?push=prefs`, 하루요약 대상). `_push.js`가 발송(하루요약 `notifyDailyDigest`=관심지역 반경 신규 협찬 1건, 이벤트 브로드캐스트 `?push=broadcast`=전체). `campaign_events(campaign_id, kind, visitor_key, created_at)`=조회/클릭 이벤트(위 `?clickstats=1` 집계원). 상세 [[frontend]]·`docs/product/16-push-notifications.md`
- `reviews(...)` — 후기(네이버 블로그). `user_id`(작성자), `hidden`, `post_date`(블로그 게시일), `click_count`(후기 카드 클릭수 누적). 어드민 후기 관리 + 공개 목록 `mine` 플래그(본인 삭제). 클릭 트래킹: 공개 후기 카드 클릭 시 `POST /api/places?reviews=track&id=`로 `click_count` +1(dedup 없이 단순 누적), `toReview`·어드민 목록(`?reviews=all`)이 `clickCount` 반환, 어드민 '후기 관리' 탭에 클릭수 컬럼 표시

- DB 컬럼은 snake_case, API 응답은 camelCase로 변환 (`toCampaign()`, `toPlace()` 같은 변환 함수가 각 핸들러 상단에 있음)

## 인덱스 (읽기량 직결 — 2026-08-31 추가)
- `idx_scraped_status_seen(status, auto_seen)` — 오토파일럿 대기조회(`status='pending' AND auto_seen=0`)가 `scraped_items` 전수스캔하던 것 방지. 쿼리는 `COALESCE(auto_seen,0)` 금지(인덱스 무력화) — `auto_seen`은 NULL 없이 0/1.
- `idx_campaigns_link(link)` — `insertCampaign`의 링크 중복확인(`WHERE link=?`)이 `campaigns` 전수스캔하던 것 방지.
- `idx_campaigns_platform(platform)`(2026-09-25) — 플랫폼별 캠페인 조회(`WHERE platform='레뷰'` 등: `?clickstats=1` 플랫폼 집계·유지보수 스윕)가 `campaigns` 전수스캔하던 것 방지. 쿼리플랜 `SEARCH ... USING COVERING INDEX` 확인.
- `idx_places_lat_lng(lat, lng)` — `insertPlace` 중복확인은 이 좌표 인덱스로 근처만 읽고 이름은 앱에서 비교(`REPLACE(name)` 같은 함수 WHERE는 인덱스를 죽이니 금지).
- **원칙**: 크롤러가 매 패스/매 아이템 실행하는 쿼리의 WHERE 컬럼은 반드시 인덱스. Turso는 스캔한 행을 전부 rows-read로 카운트 → 인덱스 없는 전수스캔이 읽기 한도 폭증의 주원인이었음. 새 핫패스 쿼리는 `EXPLAIN QUERY PLAN`으로 `SEARCH ... USING INDEX` 확인. 운영 런북 [[15-operations]] 10절.
