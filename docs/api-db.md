# API / 데이터베이스

## 구성
- Vercel 서버리스 함수 (`api/*.js`) + Turso(libSQL) — `api/_db.js`의 `getDb()`로 클라이언트 생성 (`TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` 환경변수 필요)
- `schema.sql`: 테이블 정의 원본. 실제 운영 DB 스키마 변경은 각 API 핸들러 내 `ALTER TABLE ... ADD COLUMN` try/catch 패턴으로 점진 적용되는 경우가 있음 (예: `campaigns.js`의 `source` 컬럼)
- **환경변수**: 위 Turso 2개 + `SESSION_SECRET`·`ADMIN_PASSWORD`·`PUBLIC_BASE_URL`·카카오/네이버 OAuth·`NAVER_SEARCH_*`. **오토파일럿용 추가**: `OPENAI_API_KEY`(AI 판정), 선택 `OPENAI_MODEL`(기본 gpt-4o-mini). (`CRON_SECRET`은 크론 폐지 2026-08-30로 불필요 — 수동 autopilot은 관리자 인증만으로 접근) **지오코딩(2026-08-30)**: `NAVER_MAPS_KEY_ID`/`NAVER_MAPS_KEY`(네이버 NCP Geocoding, 주소→좌표. 지도 스크립트 ncpKeyId와 동일 NCP 계정 — 로컬·Vercel 양쪽 등록 필요).
- **⚠️ Sensitive 변수와 `.env.local`**: 카카오/네이버 OAuth·`ADMIN_PASSWORD`·`SESSION_SECRET` 등은 Vercel에서 Sensitive라 `vercel env pull`로 **빈 값으로 내려와 로컬 파일을 덮어씀**(사고 이력). `.env.local` 수정은 [[15-operations]] 8절의 보호 훅(`.claude/hooks/protect-env-local.sh`)이 차단하므로, 값 추가는 각 콘솔에서 직접 복사해 넣는다.
- **수집 실행**: **로컬 크롤러(`scripts/crawl-worker.js`)로 단일화**(Vercel 크론 폐지 2026-08-30). 컴퓨터가 켜진 동안 전 플랫폼을 순회 수집→오토파일럿(무제한 반복). 수동 오토파일럿은 어드민 버튼(`POST ?action=autopilot`, 관리자 인증). `functions.maxDuration=300`은 그 수동 엔드포인트 시간예산으로 유지. **왜 크론 폐지**: 크론은 디너의여왕만 커버 + 06:00에 컴퓨터 켜져 있으면 로컬 크롤러와 오토파일럿이 겹쳐 중복매장 생성 위험. 상세 `docs/product/03-platform-analysis.md` 8절.

## 엔드포인트
- `api/places.js` — 장소 CRUD. **공개 GET은 숨김 매장 제외 + `founderEmail`(PII) 제거**, `?admin=1` 서버사이드 조회는 `requireAdmin`(이메일 포함). 제보 POST에 레이트리밋(IP당 1분 15회), 이메일은 로그인 사용자만 `userId`로 `users`에서 조회해 저장(비로그인 미수집). 후기(리뷰) 라우팅도 합쳐짐(`?reviews=`). **사이트 방문 집계도 합쳐짐(`?visit=`)**: 공개 페이지 로드 시 `POST ?visit=1`(app.js `loadInitialData`에서 fire-and-forget)로 `site_daily`에 PV +1 / `site_visitor`(IP+KST일자 PK)로 UV 중복제거 후 +1(fail-open), `GET ?visit=stats`(requireAdmin)는 오늘·누적 PV/UV + 최근 7일 반환(어드민 대시보드 방문 카드). **공개 GET 엣지 캐싱(2026-08-30)**: `Cache-Control: public, s-maxage=300, stale-while-revalidate=600` — 방문자마다 전체 매장 조회(~4초)하던 것을 CDN 히트로. 어드민(`?admin=1`)·쓰기·visit은 캐시 대상 아님
- `api/campaigns.js` — 협찬 캠페인 CRUD + 조회/클릭수 트래킹(`POST ?track=view|click&id=`). `view_count`/`click_count` 컬럼에 누적하며 `campaign_events(campaign_id, kind, visitor_key)` UNIQUE로 **IP+일자 기준 중복 제거**(클라이언트는 세션당 view 1회 디바운스). 표시는 아직 안 하고 데이터만 선누적(소급 불가). 함수 12개 제한 때문에 별도 엔드포인트 분리 없이 campaigns.js에 합침. `PATCH`는 두 갈래: 바디에 `platform` 없이 `hidden`만 오면 **hidden 토글만(부분 업데이트)** 처리(신고 목록의 캠페인 숨김/노출용), 그 외엔 전체 필드 수정. **공개 GET은 숨김 캠페인 + 숨김 매장 소속 캠페인 제외 + `reporterEmail`(PII) 제거**, `?admin=1` 조회는 `requireAdmin`. **`?active=1`이면 만료(마감 지난) 캠페인도 제외**(KST 기준) — 공개 앱(`loadInitialData`)은 이걸 써서 페이로드를 활성만으로 줄임(만료분은 화면에 안 쓰임, 매일 수집으로 무한증가 방지). 어드민 대시보드는 통계용으로 전체(무필터)를 받음. 제보 POST 레이트리밋(1분 15회), 이메일은 로그인 사용자만 DB 조회 저장(비로그인 미수집). **데이터 수집 액션도 합쳐짐**(`?action=`, 함수 12개 제한): `scrape`(증분 수집→`scraped_items` 적재), `staged`/`runs`(조회), `review`/`bulkreview`/`editstaged`(승인·반려·수정) — 모두 `requireAdmin`. **`?action=autopilot`(AI 자동등록)**: 관리자 인증(requireAdmin) 또는 `Authorization: Bearer CRON_SECRET`(레거시, 현재 미사용), `?dry=1` 미리보기(쓰기 없음), `?scrape=dinnerqueen`이면 오토파일럿 후 수집도 실행. 실제 라우팅은 `_autopilot.js`. **평소 수집은 로컬 크롤러가 `runScrape`/`runAutopilot`를 직접 호출**(Vercel 크론 폐지 2026-08-30); 이 엔드포인트는 어드민 [지금 실행]/[미리보기] 버튼용. `campaigns.source`에 `'ai'`(자동등록)/`'admin'`(수집 승인)/`'user'`(유저 제보) 구분. **공개 GET 엣지 캐싱(2026-08-30)**: `?active=1` 등 공개 조회에 `Cache-Control: public, s-maxage=300, stale-while-revalidate=600`(활성 캠페인 1.2만 행 조회 ~6초 → CDN 히트 ~0.3초, 크롤 하루 단위 갱신이라 5분 지연 무해). 어드민·쓰기는 캐시 안 함.
- `api/reports.js` — 신고 처리. **매장/캠페인/후기 3종**(`target_type` + `campaign_id`/`place_id`/`review_id`, 모두 nullable). `POST`는 `targetType`+해당 id 저장(공개), `GET`은 타입별 대상명 조인(**requireAdmin**, 신고 목록=관리자 전용), `DELETE`는 신고기록 단순 삭제(관리자).
- `api/banners.js` — 상단 배너 관리. **공개 GET은 숨김 배너 제외**(관리자 쿠키 `mh_admin` 있으면 전체 반환 — 숨김 관리용), 쓰기(POST/PATCH/DELETE)는 `requireAdmin`
- `api/_ratelimit.js` — Turso 공유 카운터 기반 고정 윈도우 레이트리밋 헬퍼(`_` 접두, 함수 카운트 제외). 어드민 로그인(5분 8회)·search-place(1분 40회)·공개 쓰기(제보/신고 1분 15회, 후기 검증 20/등록 15)에 적용. 저장 실패 시 fail-open
- `api/_scrape.js` — 서버 사이드 증분 수집기(`_` 접두). **플랫폼별 러너**: `runDinnerqueen`(커서 `last_max_id`)·`runGangnam`(강남맛집)·`runRingble`(링블)·`runSeouloba`(서울오빠)·`runFoblog`(포블로그)·`runReviewnote`(리뷰노트, **무인증 v2 공개 API `/api/v2/campaigns?page=N&city=시도`를 17개 시/도별로 순회**+지역별 페이지 커서(`scrape_state '리뷰노트:서울'` 등) — SSG `/campaigns`는 page/필터 무시 96건 고정이라 v2로 전환, `city=`만 지역필터로 작동(sido=·region= 등은 무시). 디너의여왕처럼 지역별이라 랭킹변동 영향 적고 체계적 완주. 매장명+지역 로컬검색으로 도로명 해석, 이름변형 재시도+비매장 제외로 해석률 99%) — `runScrape`가 분기. 각 파서만 다르고 정규화·`classify`·적재는 공용. **`classify`(2026-08-30): 이름 + 지역(시/군/구) 매칭** — 같은 이름이라도 시/군/구 다르면 다른 지점(`new_place`), 활성 채널중복은 `dup_active`. **`rbHoursDays`(서울오빠·링블 공용 방문가능시간 파서)**: 요일 라벨 보존(`화~금 10:00~21:00 / 토 …`)·한글시간 정규화(`오후 5시`→`17:00`)·안내문 제거·요일"/"공유 인식. 서울오빠는 채널 대괄호 없으면 블로그 기본. `deadlineTs` 시간예산 초과 시 중단(커서가 다음 실행에서 이어받음). `reparsePending`도 제공. `campaigns.js`가 import.
- `api/_autopilot.js` — **AI 자동등록 라우팅 엔진**(`_` 접두). `runAutopilot({db, dry, deadlineTs})`가 `scraped_items`(pending·`auto_seen=0`)를 3갈래 라우팅: 🟢자동등록(매장·캠페인 INSERT, `source='ai'`, 제보자 비움, `status='registered'`)/🟡검수대기(`auto_seen=1` + `auto_note`, pending 유지)/🔴스킵(`status='rejected'`). 규칙(classify/flags)이 대부분 처리, AI는 신규매장 후보에만. `deadlineTs` 시간예산.
- `api/_ai.js` — 오토파일럿 AI 판정(`_` 접두). `judgeCandidate`가 OpenAI/GPT를 `fetch` 직접 호출(SDK 의존성 없음, `OPENAI_API_KEY`·기본모델 `gpt-4o-mini`). 카테고리 정합·내용 신뢰성·fuzzy 중복 판정. **페일세이프**: 키없음·실패·저신뢰(<0.85)·중복의심이면 approve=false(→검수큐).
- `api/_geocode.js` — 서버 사이드 지오코딩(`_` 접두). **①네이버 NCP Geocoding API로 주소→좌표(건물단위 정확)를 우선**(`NAVER_MAPS_KEY_ID`/`NAVER_MAPS_KEY`) → **②실패 시에만 로컬검색(POI, 이름기반) 폴백하되 결과의 시/도·시군구가 목표 주소와 일치하는 것만 채택**(`regionMatch`). 한국 좌표 범위 밖이면 null(→검수큐). **왜 바뀌었나(2026-08-30)**: 구버전은 이름기반 로컬검색만 써서 "데몬프리다이빙 광주"→남원 지점 같은 프랜차이즈 오매칭으로 좌표가 틀렸음(강남맛집·디너의여왕은 링크/브라우저 좌표라 무사). 서버(로컬 크롤러/크론)엔 브라우저 geocode(`naver.maps.Service`)를 못 써서 서버 REST로 도입.
- `api/search-place.js` — 장소명 검색 (네이버 장소 검색 연동으로 추정, 협찬 제보하기 step1 매장명 검색에 사용)
- `api/users.js` — `GET`만 지원. 기본은 회원 전체 목록(어드민 회원 목록용, 이메일 포함), `?leaderboard=1` 쿼리 시 매장 등록 수 1위 회원의 닉네임/개수만 반환(공개 화면의 "제보왕" 배너용, PII 노출 없음). 별도 엔드포인트로 분리하지 않고 합친 이유는 Vercel Hobby 플랜의 서버리스 함수 12개 제한 때문 (아래 참고). **현재 공개 화면의 제보왕 배너는 `app.js`의 `LEADERBOARD_ENABLED=false` 플래그로 비노출 상태**(베타 이벤트 시작 시 true로) — API 자체는 살아있음.
- `api/auth/` — 카카오/네이버 간편로그인
  - `login.js` (`GET ?provider=kakao&redirectTo=...` → OAuth authorize URL로 302), `callback.js` (code 교환 → `users` upsert → 세션 쿠키 발급. **재로그인 시 OAuth 이메일이 비어있으면(카카오) 기존 `email`을 덮어쓰지 않고 보존** — '내 정보'에서 직접 넣은 이메일이 매 로그인마다 지워지지 않도록. **세션 쿠키에는 email을 담지 않음(최소노출)**), `logout.js`, `me.js` (현재 로그인 사용자 조회, DB에서 `url_platform`/`url_id`/`email` 조회해 함께 응답), `profile.js` (`POST`, 세션 필요 → `users.url_platform`/`url_id` **및 `email`** 갱신(users 테이블) — 추가정보입력/내정보 시트에서 이메일을 선택 입력받음. **특히 카카오는 OAuth 이메일이 비어 여기서 직접 수취**. 세션 쿠키엔 email 미포함이며, 제보/신고 시 `founder_email`/`reporter_email`은 세션의 `userId`로 `users`에서 조회해 채움), `delete-account.js` (`POST`, 세션 필요 → `users` row 삭제 + `campaigns.user_id`/`places.founder_user_id`/`reviews.user_id` NULL 처리 + 본인 좋아요(`review_likes`) 삭제 + 세션 쿠키 삭제)
  - `_session.js`/`_state.js`: Node 내장 `crypto` HMAC로 세션/CSRF state를 직접 서명 (jsonwebtoken 등 의존성 추가 없음). `SESSION_SECRET` 환경변수 필요. 세션 쿠키 payload는 `userId`/`nickname`/`provider`/`exp`만 포함(**email 미포함 — 최소노출**). 로그인 사용자의 제보/신고 이메일은 세션의 `userId`로 `users` 테이블에서 조회해 채움 (`api/campaigns.js`, `api/places.js`). `login.js`는 `redirectTo`를 상대경로로 정규화 후 state에 저장하고 `callback.js`에서도 재차 차단(오픈 리다이렉트 방지). OAuth `redirect_uri`의 베이스 URL은 `PUBLIC_BASE_URL` 환경변수로 고정(`_http.js`)
  - `_admin.js`: **어드민 서버사이드 인증**(2026-06-29). `process.env.ADMIN_PASSWORD`(Vercel 환경변수, 필수)와 타이밍안전 비교 + SESSION_SECRET HMAC으로 어드민 쿠키(`mh_admin`) 발급/검증. `requireAdmin(req,res)`/`isAdmin(req)` 헬퍼. 어드민 로그인 = `POST /api/auth/login?admin=1 {password}`(login.js에 분기), 로그아웃은 logout.js가 어드민 쿠키도 정리. **게이트 적용**: `/api/users` 전체목록 GET, `campaigns`·`places`·`reports`의 PATCH/DELETE, `banners` 쓰기 = 관리자만. **공개 유지**: 제보(POST campaigns/places, places PATCH은 category 보정만)·신고(POST reports)·view/click 트래킹·`?leaderboard=1`·지도 GET. (과거 admin.js 하드코딩 `wonu1982`+무인증 갭 해소)
  - `_provider.js`: provider별 OAuth 설정(엔드포인트, clientId/secret, 프로필 파싱)을 모아둔 곳. 새 provider 추가 시 여기에 설정 객체만 추가. **현재 `parseProfile`이 수집하는 건 `providerUserId` + `nickname` + `email`뿐**(프로필 이미지·성별·나이 등은 수집/저장 안 함 — 개인정보 최소수집). 항목을 늘리려면 ① 카카오/네이버 콘솔의 동의항목(scope) 추가 ② `parseProfile`에 필드 추가 ③ `users` 테이블 컬럼 추가 ④ **개인정보처리방침(`policy/`) 갱신**이 한 세트로 필요
  - 세션 쿠키는 `HttpOnly; Secure; SameSite=Lax`. 로그인 사용자의 `reporter_nickname`/`founder_nickname`은 클라이언트 입력 대신 세션 닉네임을 우선 사용 (`api/campaigns.js`, `api/places.js`)

## 테이블 스키마 요약 (`schema.sql`)
- `users(id, provider, provider_user_id, nickname, email, url_platform, url_id, created_at)` — 카카오/네이버 로그인 사용자. `(provider, provider_user_id)` UNIQUE. `url_platform`/`url_id`는 프로필 설정에서 미리 등록해두는 블로그/인스타그램 링크(제보·신고 폼 자동입력용)
- `places(id, name, address, lat, lng, category, founder_nickname, founder_email, founder_url, founder_user_id, created_at)`
- `campaigns(id, place_id, platform, channels, content, deadline, link, operating_days, operating_hours, exclude_holiday, reporter_nickname, reporter_email, reporter_blog, reporter_instagram, reporter_url, source, hidden, user_id, created_at)`
  - `deadline`은 빈 문자열 허용(마감일 없음), `source`는 등록 경로 구분: `'user'`(유저 제보)/`'admin'`(수집 승인)/`'ai'`(오토파일럿 자동등록)/`'unknown'`
  - `user_id`/`founder_user_id`는 로그인 사용자 식별용 nullable FK (`users.id`). 비로그인 제보도 계속 허용하므로 NULL 가능
- `banners(id, image_url, link_url, start_date, end_date, created_at)`
- `reports(id, target_type, campaign_id, place_id, review_id, reason, detail, user_id, created_at)` — 신고 3종(`target_type`='place'|'campaign'|'review', 해당 id만 채움, 나머지 NULL). `user_id`는 로그인 사용자가 신고 시 세션에서 조용히 채워짐(입력 필드 없음). 비로그인 신고는 NULL. (기존 campaign_id NOT NULL 스키마에서 2026-07-02 재구성)
- `user_visits(user_id, visit_date)` — 로그인 사용자 접속 집계(1일 1회, `UNIQUE(user_id, visit_date)`). `me.js`가 로드 시 KST 날짜로 `INSERT OR IGNORE`. 어드민 회원 목록의 "접속수"에 사용
- `site_daily(visit_date PK, pv, uv)` / `site_visitor(visit_date, visitor_key, PK(visit_date,visitor_key))` / `site_referrer(ref PK, cnt)` — **전체 사이트 방문 집계**(비로그인 포함). `places.js ?visit=1`이 PV 누적 + IP 기준 UV 중복제거 + `document.referrer`를 `classifyReferrer`로 채널 분류해 `site_referrer` 누적. 어드민 대시보드 "방문 카드/추이 그래프(일·주·월)/유입경로"(`?visit=stats[&period=]`). KST 일자 기준
- `scraped_items(id, platform, source_id, source_url, name, address, category, channel, content, deadline, hours, days, exclude_holiday, flags, dedupe_status, matched_place_id, status, created_campaign_id, auto_seen, auto_note, created_at, reviewed_at)` — **데이터 수집 스테이징(승인 대기 큐)**. `UNIQUE(platform, source_id)`+`INSERT OR IGNORE`로 멱등. `status`=pending|registered|rejected, `dedupe_status`=new_place|add_channel|renew|dup_active, `flags`=규칙 검증 경고. **오토파일럿 추적**: `auto_seen`(1=자동판정 완료, 재평가 안 함), `auto_note`(라우팅 사유, 검수큐 표시). `scrape_state(platform PK, last_max_id, last_run_at)`=증분 커서, `scrape_runs(...)`=수집/오토파일럿 실행 이력(`platform='autopilot'` 행 포함). 상세 `docs/product/03-platform-analysis.md`
- `reviews(...)` — 후기(네이버 블로그). `user_id`(작성자), `hidden`, `post_date`(블로그 게시일), `click_count`(후기 카드 클릭수 누적). 어드민 후기 관리 + 공개 목록 `mine` 플래그(본인 삭제). 클릭 트래킹: 공개 후기 카드 클릭 시 `POST /api/places?reviews=track&id=`로 `click_count` +1(dedup 없이 단순 누적), `toReview`·어드민 목록(`?reviews=all`)이 `clickCount` 반환, 어드민 '후기 관리' 탭에 클릭수 컬럼 표시

## 데이터 매핑 규칙
- DB 컬럼은 snake_case, API 응답은 camelCase로 변환 (`toCampaign()`, `toPlace()` 같은 변환 함수가 각 핸들러 상단에 있음)

## 인덱스 (읽기량 직결 — 2026-08-31 추가)
- `idx_scraped_status_seen(status, auto_seen)` — 오토파일럿 대기조회(`status='pending' AND auto_seen=0`)가 `scraped_items` 전수스캔하던 것 방지. 쿼리는 `COALESCE(auto_seen,0)` 금지(인덱스 무력화) — `auto_seen`은 NULL 없이 0/1.
- `idx_campaigns_link(link)` — `insertCampaign`의 링크 중복확인(`WHERE link=?`)이 `campaigns` 전수스캔하던 것 방지.
- `idx_places_lat_lng(lat, lng)` — `insertPlace` 중복확인은 이 좌표 인덱스로 근처만 읽고 이름은 앱에서 비교(`REPLACE(name)` 같은 함수 WHERE는 인덱스를 죽이니 금지).
- **원칙**: 크롤러가 매 패스/매 아이템 실행하는 쿼리의 WHERE 컬럼은 반드시 인덱스. Turso는 스캔한 행을 전부 rows-read로 카운트 → 인덱스 없는 전수스캔이 읽기 한도 폭증의 주원인이었음. 새 핫패스 쿼리는 `EXPLAIN QUERY PLAN`으로 `SEARCH ... USING INDEX` 확인. 운영 런북 [[15-operations]] 10절.
