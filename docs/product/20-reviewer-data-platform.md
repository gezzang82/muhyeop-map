# 20. 리뷰어 데이터 플랫폼 — 연결자에서 데이터·신뢰 플랫폼으로

> 2026-10-17 대화에서 정리된 북극성 구체화. "지금 당장 만들 것"이 아니라 **방향성·구현 순서**를 박아두는 문서. 흔들릴 때 기준점.

## 문제의식 (출발점)
현재 무협맵 = **크로스 플랫폼 체험단 디렉토리**(11개 플랫폼 캠페인을 수집·dedup·네이버 정규화해 지도에 연결). 캠페인 자체는 우리 소유가 아니라 **연결(aggregator)** 포지션 → 대체 가능성이 있어 **해자(moat)가 약함**. 다음 단계 = **우리만의 데이터·커뮤니티·신뢰 자산**을 쌓아 "연결자 → 플랫폼"으로 전환.

## 핵심 체인
```
후기(1st-party 데이터) → 유저 체험단 이력(프로필) → 게임화(수집 콘텐츠) → 신뢰도 축적 → [함께 참여/동행 매칭 해금]
                     ↑________ 블로그 자동수집으로 마찰 제거 ________↑
```

### 1) 후기 = 유저 데이터
유저가 등록한 후기가 쌓일수록 그 사람의 **체험단 포트폴리오**가 됨: 다녀온 매장·후기 수·**카테고리 분포**(맛집/뷰티 전문)·**지역 분포**·활동기간·받은 좋아요. 수집 캠페인과 달리 **우리 1st-party 데이터**.

### 2) 자동수집 = 열쇠 (마찰 제거)
리뷰어 이력은 본인 **블로그에 흩어져** 있고 수동 등록은 안 함. → **블로그만 연결하면 체험단 글을 자동 수집**해 프로필·이력 자동 생성. (이미 네이버 블로그 후기 수집 기술 보유 → 가능. 협찬/체험단 고지문 감지로 체험단 글 선별.) "손 안 대도 이력이 쌓인다" = 마찰 0 + 즉각 보상감.

### 3) 2차 콘텐츠
- **리뷰어 프로필/포트폴리오** — 본인한텐 매장·플랫폼에 보여줄 이력(선정률↑), 남한텐 탐색 콘텐츠
- **매장 상세 "이 매장 다녀온 리뷰어"** — 매장↔리뷰어 양방향
- **전문가 랭킹** — "강남 맛집 리뷰어 TOP", "뷰티 전문 리뷰어"
- **서이추 매칭** — 유사 카테고리/지역 리뷰어 연결 ([[19-community-activation]])

### 4) 게임화 = 수집 콘텐츠 (리텐션+바이럴)
리뷰어는 수집가 기질 → 이미 한 활동을 수집물로 시각화:
- **지역 스탬프** — "강남 정복", "서울 25개 구 완주", **다녀온 곳 채워지는 개인 지도**(에어비앤비 방문 스탬프 레퍼런스)
- **카테고리 배지** — "맛집 마스터 50", "뷰티 전문가", "카페 헌터" (레벨)
- **리뷰어 티어** — 활동량 기반 브론즈→실버→골드→다이아
- **마일스톤**(첫/10/50/100) · **스트릭**(N주 연속) · **희귀/시즌 한정 스탬프**
- ⚠️ **vanity로 끝내지 말 것** — 배지가 **실익(선정률)** 과 연결돼야. "뷰티 전문가 배지 = 신뢰/전문성 증명" → 블로거 진짜 KPI에 기여, 북극성(블로그 트래픽)과 정렬
- **공유 = 무료 마케팅**: 배지/스탬프 지도를 블로그·인스타 자랑 → 유입 루프

### 5) 신뢰도 레이어 → "함께 참여" 해금
데이터가 쌓이면 **신뢰도**가 생기고, **위험해서 보류했던 기능이 안전해짐**. (전에 "체험 동행 매칭"을 **안전/신뢰 리스크로 보류** → [[06-decision-log]] 2026-10-13. 신뢰도 레이어가 그 문제를 해결.)
- **공동 참여 캠페인** — 2명+ 필요한 체험단을 검증 리뷰어끼리 매칭(매장/플랫폼 중개라 안전)
- **멘토-뉴비 매칭** — 고신뢰 리뷰어 + 초보(온보딩+결속)
- **동행 매칭** — 프로필·이력·티어 공개 + 상호 동의로 전보다 안전
- **신뢰도 게이팅** — "골드 이상만 매칭"
- **신뢰 시스템**: 검증 블로그 이력 + 배지 + **동행 후 상호 매너 평가** + 신고/차단 → "믿고 함께할 리뷰어 찾는 곳" = **신뢰 그래프 해자**

## 왜 해자인가
타 플랫폼은 **자기 캠페인만** 봄. 무협맵은 리뷰어의 **크로스 플랫폼 전체 이력 + 신뢰 그래프**를 가짐 → 단일 플랫폼이 복제 불가. 데이터↔콘텐츠↔유입 플라이휠.

## 구현 순서 (중요 — 순서 틀리면 위험)
1. **데이터 토대** (진행 중) — 네이버 정규화·카테고리·후기 기능 (스탬프 판정의 전제: 지역/카테고리 정확해야 "강남 정복" 가능)
2. **블로그 자동수집** — 프로필 자동 생성(마찰 제거)
3. **프로필/게임화** — 스탬프·배지·티어
4. **신뢰도 축적** — 평가·검증
5. **함께 참여/동행 매칭** — 신뢰도 쌓인 뒤에만. **신뢰도 없이 매칭부터 하면 위험**(보류 이유).

## 리스크/고민
- **블로그 자동수집 동의·범위** — 본인 연결·동의한 블로그만. 개인정보처리방침 반영
- **체험단 글 판별 정확도** — 고지문 없는 글
- **공개 범위** — 이력 공개(탐색) vs 비공개(본인 포트폴리오) 유저 선택
- **동행 안전** — 인앱 한정·검증 전용·상호 동의·신고/차단. 저위험 형태(공동참여 캠페인)부터
- **수익 연결 가능성** — 프리미엄 매칭·전문가 노출 등(단 유저 규모 선결, [[04-revenue-model]])

## IA — MY의 분화 + 공개 리뷰어 프로필 (2026-10-17)
현재 MY = "설정 + 내 활동"이 한 사적 공간에 섞임. 결국 둘로 분리돼야 함:
- **설정/계정 (MY, 축소·비공개)**: 내 정보·알림설정·약관·로그아웃·탈퇴 (본인만)
- **리뷰어 프로필 (별도·공개)**: 후기·배지·스탬프·이력·전문분야·티어 → **다른 유저가 볼 수 있음**
무게중심이 "MY=내 설정함" → **"프로필=공개 명함"** 으로 이동. 공개가 중요한 이유: ①명함/포트폴리오(선정률↑) ②탐색 콘텐츠(팔로우·서이추 루프) ③**공개 프로필 URL(`/u/닉네임`)을 블로그·인스타에 공유 → 유입 바이럴** ④배지·티어 공개 = 동행매칭 신뢰 근거.
**프라이버시 필수**: 내 장소(집/회사 좌표) **절대 비공개**, 공개/비공개 토글(유저 선택), 공개 프로필에 이메일·연락처 노출 금지.

## 자동수집 PoC 검증 (2026-10-17)
네이버 블로그 자동수집 **실현 가능 확인**(블로그 2곳 각 최근 20글). RSS로 글목록(블로그당 50개)·PostView 본문(6~7천자) 수집 OK(인증·검색쿼터 무관). 텍스트 고지문 감지(협찬/제공받아/체험단/무료제공 등) **정밀도 높음**(잡힌 건 전부 진짜 체험단, 미감지는 실제 내돈내산). **한계**: 이미지로만 된 고지문은 미감지(recall) → Phase2에서 이미지/OCR 보완 또는 유저 원탭 확인(semi-auto). RSS는 최근 ~50글만 → 전체 이력은 글목록 페이지네이션 필요. 스크립트: 세션 tmp `blog-poc.cjs`.

## 블로그 글 → 후기 자동매칭 등록 스펙 (2026-11-06, PoC 검증 완료)
PoC(위)가 "블로그를 읽고 체험단 글을 **선별**"까지라면, 이건 그 글들을 **우리 매장(place)에 매칭해 후기로 일괄 등록**하는 스펙. **일일이 수동이 아니라 "AI 자동매칭 → 고신뢰 자동등록 + 애매한 것만 일괄확인"** (오토파일럿과 동일 패턴). 네이버 로그인만으론 블로그 글 목록을 못 받음(OAuth=프로필만, 글쓰기 API=쓰기전용) → **공개 RSS**로 가져옴(권한 불필요, 우리는 이미 유저 블로그ID 보유=프로필 `url_platform=naver`/`url_id`).

### 유저 조건(자격)
- **필수**: ①로그인(후기=user_id 귀속) ②프로필에 **네이버 블로그** 등록(`url_platform='naver'`+`url_id`; 인스타만=해당 안 됨, 블로그 RSS 필요) ③블로그 RSS 접근 가능(비공개면 불가 안내).
- **신뢰/악용 방지**: ④⚠️**본인 블로그 소유** — 프로필 블로그는 현재 자가등록(미검증) → 남의 유명 블로그로 가짜 포트폴리오 위험. **MVP는 자가등록 신뢰, Phase2 소유검증**(블로그에 인증코드 노출 등). ⑤**중복 방지**(이미 등록된 글=같은 URL 재등록 스킵) ⑥**레이트리밋**(대량 등록 악용 차단).
- **고려**: ⑦가져온 후기 **공개/비공개** 유저 선택(공개 프로필 노출 여부, 위 IA).

### 파이프라인
1. **수집**: `rss.blog.naver.com/{블로그ID}.xml`로 최근 글(제목·링크·날짜·요약, ~50개). 전체 이력은 글목록 페이지네이션(Phase2).
2. **선별+추출(AI 1회 배치)**: 제목+요약 → `{isStoreReview, storeName, region}`. isStoreReview=방문형 특정 상호 후기만(명소·공원·일상글 false). storeName=지점명 포함 정식상호(수식어·업종 제외), region=시/구/동·역명. (오토파일럿 `_ai` 재사용)
3. **매장 매칭(핵심)**: storeName(공백무시 LIKE) → `places` 후보 → region으로 좁힘(주소 포함) → **`naverCanonicalName` 교차검증**(정식명 일치). 기술 전부 **오토파일럿/크롤러에 이미 있음**(`_autopilot.naverCanonicalName`, `insertPlace` 퍼지 dedup).
4. **신뢰도 게이트**: 🟢**이름+지역 둘 다 매칭=자동등록** / 🟡이름만 or 지역 불일치=**일괄확인 큐** / 🔴DB에 없는 매장=매장 신규등록 후 등록 or 스킵.
5. **등록**: 기존 `reviews`(place_id, url=블로그링크, title, post_date, user_id) 그대로 재사용.

### PoC 검증 결과 (실데이터, 블로그 "개짱트립" 15글)
- **후기글 14 / DB매칭 14(100%) / 고신뢰자동 9 · 확인 5**. 비후기(카이스트 오리연못) 정확히 제외.
- **🟢 자동(9)은 전부 정답.** **게이트가 핵심 안전장치 입증**: "하루"(산본역 술집)가 엉뚱하게 **광진구 "하루"에 오매칭**됐으나 **지역 불일치로 🟡확인큐에 정확히 걸러짐 → 무확인 오등록 0건.**
- ⚠️ **100% 매칭은 체험단 전업 블로거라 그럼**(우리가 크롤링한 체험단 매장을 다님). **일반/비체험 비중 높은 블로그는 매칭률↓** → 🔴(DB없음)·비후기 비율 올라감. 스크립트: 세션 tmp `match-poc.cjs`.

### UX (= "매칭해서 등록")
"블로그 글 23개 불러옴 → ✅18개 매장 자동매칭(확인만) + ❓5개 매장 골라주세요" → 유저 **한 번 쓱 확인 → 일괄 등록**(글마다 매장 고르는 수동 아님). 블로거 체감 = "쌓인 글 수십 개가 몇 탭으로 후기화".

### 리스크/원칙
- **무확인 전량자동 금지** — "하루" 사례처럼 오매칭 발생 → **반드시 게이트(이름+지역 둘 다 맞아야 자동)**.
- **후기 아닌 글 분류** — AI isStoreReview로 1차 거름(이미지-only 고지문 recall 한계는 semi-auto 확인).
- **동의·공개범위·소유검증** — 위 유저 조건 ④⑦.
- **MVP 범위**: "RSS 불러오기 → AI 매칭 → 🟢자동등록 + 🟡일괄확인" 한 사이클. **전체이력 페이지네이션·이미지 OCR·블로그 소유검증은 Phase2.**

### 스케일 전략 (대량 글, 예: 체험단 글 1000개)
- **MVP 한계(명시 필수)**: 수집은 **RSS = 최근 ~50개만**. 1000개 유저여도 최근 ~50개만 불러와지고 나머지는 안 보임. commit도 글마다 `validateAndExtract`가 네이버를 fetch해 **상한 40건/요청**(1000개=서버리스 300s 타임아웃). → MVP는 "최근 것 전용". **UI에 "최근 N개를 불러왔어요"로 정직히 표기**(전체인 척 금지 — "내 글 1000갠데 왜 50개?" 컴플레인 방지).
- **Phase2(전체 이력)**: ①**글목록 페이지네이션** — RSS 대신 블로그 글목록 페이지를 넘겨 크롤(전체 확보) ②**백그라운드 처리** — 한 요청에 다 하면 타임아웃 → 크롤러처럼 큐로 점진 처리("1000개 중 340개 매칭 중…") + 완료 시 푸시(크롤러 인프라 재사용) ③**배치 commit**(20~40씩) ④비용/레이트 가드(등록분 aggressive 스킵, AI/fetch 호출 상한).
- **판단**: 1000개 파워유저는 소수 → MVP(최근50+한계명시) 출시 후 반응 보고 Phase2. 처음부터 1000개 엔진=과설계.

### 구현 착수 메모(다음 세션)
- **서버**(함수 12개 제한 → 신규파일 금지, 기존에 분기): ①`?blogimport=list` RSS수집+AI추출+매칭 → `[{post, matchedPlace?, confidence}]` 반환 ②`?blogimport=commit` 일괄 등록(선택분 reviews INSERT, 중복 URL 스킵, 레이트리밋). `users.js`나 `places.js`(reviews 이미 있음)에 분기.
