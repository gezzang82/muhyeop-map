# 매일 스레드(Threads) 글 — 반복 작업 패턴

> 원우씨 역할 = **매일 스레드에 올릴 글 담당자**. 어시스턴트가 초안을 쓰고, 원우씨가 컴펌 후 직접 게시한다.
> 깃/코드 내용은 **사실 확인용으로만** 쓰고, 결과물은 항상 **바로 복붙 가능한 글**이어야 한다.

## 답변 규칙 (어시스턴트가 지킬 것)

1. **10줄 이내.** 해설·근거·옵션 나열 금지. 글 본문 + 한 줄 안내가 전부.
2. **쉬운 말만.** 개발 용어(API·bbox·크롤러 등) 절대 쓰지 않음. 일반 사용자 기준.
3. **기본 1개.** 하루 글 1개를 완성형으로. 더 달라고 하면 최대 3개.
4. 고쳐달라고 하면 **다시 쓴 글만** 보여준다(무엇을 왜 고쳤는지 설명 금지).

## 글 자체의 규칙

- **첫 줄이 전부**: 설명이 아니라 **장면**으로 시작 (예: "홍대 맛집에 당첨됐다. 근데 나 홍대 안 산다.")
- **동료 톤**: "써보세요" ❌ / "나도 리뷰어인데 불편해서 만들었다" ⭕
- **마지막은 질문**으로 닫아 댓글 유도 (댓글이 노출을 키움)
- **500자 이내**, 짧은 문단 + 빈 줄로 끊기 (모바일 가독성)
- **금지**: "최고의·국내 유일" 같은 과장, 광고 문구, 허위·미확인 숫자
- **숫자는 `[ ]` 표시**로 넣어 원우씨가 올리기 전 확인 (예: 플랫폼 [10]곳)
- **링크는 본문 금지 → 올린 뒤 첫 댓글**에 `muhyeop.com/?ref=threads`
  (카톡·오픈채팅 공유는 `?ref=kakao`. 어드민 "일별 유입경로"에서 채널별 유입이 숫자로 잡힘)

## 소재 5종 로테이션 (같은 각도 연속 금지)

| # | 각도 | 핵심 메시지 |
|---|------|-------------|
| 1 | 공감(창업 스토리) | 안 사는 동네 당첨 → 주소 리스트론 근처를 모름 → **동선 묶기**가 지도의 이유 |
| 2 | 꿀팁 | 고수는 "당첨된 곳"이 아니라 **그 동네를 턴다**(하루 2~3탕) |
| 3 | 플랫폼 흩어짐 | 사이트 7개 탭 → **협찬 찾는 시간이 신청 시간보다 길다** |
| 4 | 빌드인퍼블릭 | 리뷰어가 만든 중 / 된 것·안 된 것 솔직히 / **광고·수수료 없음** |
| 5 | 후기 | 매장 평가 ❌ **리뷰어끼리 서로 조회수 나눠 갖기** ⭕ (내 후기 → 내 블로그 유입) |

- 1·3은 둘 다 불만 토로라 **연속 배치 금지**. 사이에 2·4·5를 끼운다.
- 사실 근거는 [01-service-vision](01-service-vision.md)(출발점)·[11-competition](11-competition.md)·[06-decision-log](06-decision-log.md) 참고.

## 계정 톤 — 원우씨 개인 계정 (2026-09-19 확정)

- **글은 원우씨 1인칭**으로 쓴다(대필). "내가 리뷰어인데 불편해서 만들었다" 톤. 브랜드 공지 톤 ❌.
- **담당자 ≠ 원우씨**(지인이 대신 작성·게시). 따라서 **경험담을 지어내지 않는다** — 실제 이야기는
  [01-service-vision](01-service-vision.md) "출발점"(홍대 당첨 → 동선 묶기), [06-decision-log](06-decision-log.md) 등
  문서에 있는 사실만 쓰고, 새 에피소드가 필요하면 **원우씨 확인 필요**로 표시해 넘긴다.
- 개인 계정이므로 소재 **①창업 스토리·④빌드인퍼블릭(내 얘기)** 을 주력으로, ②⑤는 사이에 끼워 변화를 준다.
