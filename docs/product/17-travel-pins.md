# 내 장소(저장한 곳) + 하단 GNB — 리텐션 개편 (Phase 1 계획)

> 상태: **방향·설계서 확정 → Phase 1 실행 계획 수립.** 설계서 9화면(Figma `Phase1` 페이지) 기준, 아래 "Phase 구분"의 Phase 1 체크리스트가 이번 고도화 범위. 네이밍·웹푸시 등은 열린 항목(문서 하단).
> 발단: 스레드 유저 요청 — "내가 갈 여행지(예: 속초 대포항)를 핀으로 저장하면 그 주변 협찬을 쉽게 보고 싶다." + 리텐션 논의에서 파생. 이후 **집/회사/+ (모빌리티 스타일)** 기본을 넣기로 하며 개념이 '여행지' → **'내 장소'(집·회사·여행지 등)** 로 일반화됨.

## 왜 (문제/목표)
- 트래픽(PV/UV)은 스파이크가 나도 **재방문으로 안 이어지면 새는 양동이** → 조회수 계단식 상승 불가. 지금 계기판이 PV/UV뿐이라 **리텐션/이탈을 못 봄**.
- 무협맵 사용은 **에피소딕**("다음 체험단 필요할 때만") → 목표는 DAU가 아니라 **"필요한 순간 다시 부르기"(재방문 트리거)**.
- **저장한 장소 = 유저가 스스로 의도(intent)를 남기는 것** → "○○ 근처 새 협찬 3건" 으로 정확한 순간에 재방문 유도. 리텐션 엔진.
  - **집/회사(상시 앵커)** = "우리 동네 새 협찬" 반복 확인 → 일상적 재방문 훅(리텐션 베이스↑).
  - **여행지(에피소딕)** = 여행 때 그 주변 협찬 → 그 스레드 유저의 원래 니즈.
  - 둘은 **같은 기능**(위치+반경+카테고리+알림)의 다른 쓰임.

## 핵심 원칙
- **데이터 한 몸 · 화면 분리 · 서로 링크**: 같은 장소 데이터를, 홈=지도 뷰 / 내 장소=목록 뷰로.
- **지도는 "지금 신청 가능"만** 순수하게 유지(협찬종료 노이즈 방지, [[06-decision-log]]).
- **후기는 매장 중심** — 캠페인이 아니라 매장에 연결.

## IA: 하단 GNB 5탭 (모바일)
`홈 · 내 장소 · 커뮤니티 · 마이페이지 · 메뉴` — **제보하기 탭 제거**(피벗: 제보↓·후기↑).
- **홈** = 지도(탐색) + 저장 장소 **앵커/화면밖 방향표시**("어디쪽이더라" 해결)
- **내 장소** = 목록 화면(아래 상세). 모빌리티 스타일 **집 / 회사 / + 추가**.
- **커뮤니티** = 후기(맨 마지막에 논의). 씨앗=후기 피드 + "최근 마감→후기 남겨주세요" 넛지 + **후기등록(매장명 아카이브 검색)**.
- **마이페이지** = "나"(아래 상세)
- **메뉴** = "서비스 정보"(아래 상세)
- **제보하기 = 완전 제거**: 유저 직접 협찬 등록 폐지(크롤러/어드민만 등록). FAB도 안 둠.
- **신고 = 컨텍스트 액션**: 매장/후기/캠페인 상세의 신고 버튼으로. 메뉴엔 일반 '문의/신고' fallback만.
- PC는 현행 좌측 아이콘레일 유지(모바일 69%), **IA(탭 구성)만 통일**.
- **탭 네이밍 보류**: '여행지'는 집/회사와 안 맞아 폐기, **'내 장소' 계열**로. 무협 테마 강도(밸런스안 "사냥터/강호" 시그니처 후보)와 함께 나중에 확정.

### 항목 라우팅 규칙 (혼선 방지)
"메뉴에 다 넣지 말고" 각 항목을 하는 일에 맞는 자리로:
- **액션**(후기등록·신고) → 그 액션이 사는 화면(커뮤니티 / 대상 상세)
- **나**(설정·로그인정보·내 활동) → 마이페이지
- **서비스 정보**(소개·약관·개인정보·운영정책·문의) → 메뉴

### 마이페이지 = "나"
- **프로필 카드**: 닉네임 + 로그인수단(카카오/네이버/애플) + SNS(블로그/인스타). *비로그인 → 로그인 CTA(저장·알림·후기 유도).*
- **내 기여(통계)**: **후기 N**(맨 앞) · 도움돼요(좋아요) N. 피벗 반영해 후기 우선. (숫자 통계만 — 목록은 커뮤니티에서)
- **내 후기 → 커뮤니티로 이동**(결정 2026-10-02, [[06-decision-log]]): 내가 등록한 후기 목록은 마이페이지가 아니라 **커뮤니티 탭 안 '내 후기만 보기' 메뉴(필터)** 로. (후기=커뮤니티 핵심 콘텐츠라 그 맥락에서 보는 게 자연스럽고 중복 화면 방지)
- **내 제보 = 폐기**(결정 2026-10-02): 유저 제보가 이미 폐지돼 '내 제보' 자산은 탈락 → 노출/구현 안 함.
- **설정** 진입(아래).
- *리텐션 앵글*: 단순 설정창이 아니라 **"내 기여/영향 확인처"**("도움돼요 12", "이번 주 내 지역 5건") → 재방문 훅.

### 설정 (마이페이지 안)
- **알림 — 두 레벨로 분리(중복 금지)**:
  - **설정 = 종류별 마스터**: `전체 알림 받기`(기기 마스터) / `내 장소 신규 협찬` / `이벤트·공지`.
  - **장소별 on/off는 '내 장소' 탭 각 카드**(집 켜고 회사 끄고 등). 설정엔 장소별 토글 넣지 않음.
  - 규칙: 설정에서 "내 장소 알림" 끄면 전체 off(마스터가 이김), 켜져 있으면 장소별 벨 따름.
  - ⚠️ **앱 전용**: 웹/iOS는 "무협맵 앱에서만" 안내(기존 `enableAreaAlert` 패턴). + **OS 권한 연동**(꺼져있으면 "기기 설정에서 알림 허용" 안내).
  - 매핑: 마스터=`push_tokens.enabled`(기기), 종류/장소별=`push_prefs.enabled`, 이벤트=broadcast 대상([[api-db]]).
- **계정**: 닉네임·이메일·SNS 수정.
- **기타**: 로그아웃 · 회원탈퇴 · (앱: 버전·캐시).

### 메뉴 = "서비스 정보"
- 무협맵 소개 · 이용약관 · 개인정보처리방침 · 운영정책 · 문의(+신고 fallback) · 버전/앱 다운로드.
- 액션·설정·정체성이 다 다른 탭으로 가서 **정적 info만 남아 얇음** → "메뉴 유지 vs 폐지(알림함/이벤트로 대체)"는 열린 항목. 지금은 **유지(단순)**, 2단계 푸시 붙일 때 재고.

## 내 장소 (저장한 곳)
**장소 = { 위치(lat/lng), 이름, 반경(km), 카테고리, 알림 on/off }** → **기존 `push_prefs`의 일반화**(관심위치 1개 → 이름 붙은 다건). 반경·카테고리·알림 필드가 그대로 매핑([[api-db]] `push_prefs`).

- **기본 프리셋(모빌리티 스타일)**: **집 / 회사 / + 추가**. 집·회사는 상시 앵커(일상 재방문), +로 여행지·자주 가는 곳 등 커스텀.
- **화면 = 목록**(선택 확정): 저장 장소 카드(이름·지역 + "모집 중 N건" 배지 + 관리) → **카드 탭 시 홈 지도로 점프 + 주변 협찬**(사이드바 재사용). "탭 눌렀는데 또 지도"를 피해 홈과 역할 분리.
- **홈 지도 쪽**: 저장 장소는 협찬 핀과 구분되는 **앵커 마커(항상 표시, 클러스터에 안 묻힘)** + 이름표, 화면 밖이면 **가장자리 "○○ →" 방향표시**.
- **찍기**: 검색(지명/관광지까지 확장) **+ 지도 롱프레스**. 대포항 같은 비매장 지점은 롱프레스 필수.
- **반경**: **장소별 설정 km**(유저 조정). "모집 중 N건" 배지는 이 반경 내 활성 협찬 기준(화면 기준이면 줌마다 출렁 → 반경 기반이 안정적).
- **카테고리**: **장소별 필터**(그 반경 내 특정 카테고리만, 예: 집은 음식점·카페만). 기존 카테고리 11종 재사용.
- **알림**: **장소별 앱푸시 옵트인** — "○○ 근처에 새 협찬" (하루요약, [[16-push-notifications]] 엔진 재사용). 협찬 0건 지역 = **"생기면 알려드릴게요" 예약**(빈 결과를 알림 옵트인으로 전환).
  - ⚠️ **앱푸시는 현재 안드로이드 앱 한정.** 웹(69%)·iOS는 저장·반경·카테고리·조회는 되나 **알림은 미작동** → 알림 혜택은 **웹 푸시/iOS 도입 후** 전체 확대. (웹 푸시가 이 기능의 진짜 리텐션 레버.)
- **저장 위치**: 로그인=서버 동기화(기기 간), 비로그인=localStorage(기기 한정·알림 불가) → **"저장·알림 받으려면 로그인"** 자연스러운 전환 트리거.

### 장소 등록 플로우 (집/회사/여행지) — 상태별
> **원칙**: 정확한 번지 불필요(반경 기반) → **동네 단위**로 충분 + 프라이버시 배려. "주소 정밀입력"이 아니라 **"지도에서 위치 맞추기"** 가 메인. 위치 설정은 인터랙션이라 **정적 1프레임 X, 상태(①~④)로 설계**.

- **① 진입(위치 설정)**: 상단 **지도 미니뷰 + 화면 중앙 고정 핀**(지도를 드래그해 핀 아래를 맞추는 방식 — 카카오맵/배민 주소설정과 동일, 한 손 조작). 핀 아래 **선택 위치 주소(동 단위) 실시간 표시**. 지도 위/아래에 **[📍 현재 위치로]**(1순위·큰 버튼) + **🔍 주소·동네·역 검색**. 하단에 상세폼(이름/반경/카테고리/알림) + **[저장]** + 프라이버시 안내 문구("정확한 주소는 필요 없어요. 동네만 맞춰도 주변 협찬을 보여드려요").
- **② 검색(🔍 탭)**: 전체화면 검색 입력 + 자동완성(동/도로명/아파트/역). 선택 → ①로 복귀하며 지도 그 위치로 이동·핀 세팅.
- **③ 현재 위치(📍 탭)**: 위치권한 요청 → 지도 현재 위치로 이동·핀 세팅(①의 변형). *집에 있을 때 원탭 완료.*
- **④ 저장 완료**: 내 장소 목록으로 복귀, 카드 생성(모집 중 N건 집계 시작).
- **프리셋별 차이**: 집·회사 = **반경 기본 2km**, 여행지 = 반경 기본 3km + ①에서 **검색/지도조정이 메인**(현재위치 아님). 이름은 프리셋 자동(수정 가능).
- **구현 인프라**: 현재위치=geolocation(기존 내위치 마커 재사용), 주소검색·좌표=`_geocode`(NCP)/네이버, 지도=naver.maps. 저장=push_prefs 다건(위 백엔드 항목).

## 커뮤니티 (상세 설계 확정 2026-10-02, [[06-decision-log]])
**IA = 단일 메인 + 세그먼트 `[서이추] [후기] [내 후기]`** (밀도 위해 GNB 탭 분리는 안 함). 서이추=활성화 엔진(게시판), 후기=콘텐츠 피드, 내 후기=후기 피드 본인 필터.

### 후기 (세그먼트) = 지도 등록 후기 피드
- **지도(매장)에 등록된 후기**를 **최신순 리스트**로. 지금은 건수 적어 전체 노출, **향후 "지역별 탭"으로 세분화**(탭 클릭 시 해당 지역). *(초기 구현의 카테고리 칩은 잠정 — 세분화 축은 지역)*
- **후기등록 진입점 3개**:
  1. 홈 지도 → **기존 매장** 상세 → 후기 탭(기존).
  2. 커뮤니티 후기 화면 → **'후기등록' 버튼** → 매장 검색 → 주소·위치 확인 → 블로그 URL 검증 → 등록.
  3. 홈 지도 **검색핀 위 말풍선 '후기등록'**.
  → ②③은 **DB에 없는 매장도 생성**해 등록(기존 홈 등록은 이미 있는 매장만이었음).
- **신규 매장 생성 = 제보 step1 재사용**: 네이버 장소검색(이름+주소) → **주소 브라우저 지오코딩으로 좌표 자동**(별도 지오코딩/서버 `_geocode` 불필요) → 없으면 `POST /api/places` → `?reviews=validate`→`?reviews=create`. 공개 생성이라 레이트리밋/검증 가드. `searchPlacesOnServer`(우리 DB 전체·죽은매장 포함)와 네이버 검색(완전 신규) 둘 다 소스.
- **카테고리 자동분류**: 네이버 검색 `category` → 서버 `categoryByKeyword`(크롤러 매퍼 재사용, 헤어/사진관/운동 분리)로 자동 매핑, '기타' 폴백. **유저 입력 없음**(틀리면 어드민/스윕 정정). [[api-db]]
- **'내 후기'(세그먼트)**: 후기 피드의 본인 필터(`?reviews=feed&mine=1`). 마이페이지 '내 후기 목록'을 이리로 이관(수정/삭제·받은 좋아요 확인). 마이페이지엔 통계만.

### 서이추 (세그먼트) = 글쓰기 게시판
리뷰어 native 행동인 **서이추(블로그 서로이웃)** 를 하는 곳. 리뷰노트 커뮤니티엔 서이추 글이 **하루 수백 개**로 폭발(수요 확실).
- **엔트리 = 프로필이미지 · 닉네임 · 작성시간 · 작성글 · 블로그주소**. **블로그 주소 등록자만** 작성/노출(품질 게이트). 탭 → 블로그 이웃추가.
- **저허들 활성화 엔진**: 블로그만 있으면 글 작성(후기 불필요). → 서이추(활성화) ↔ 후기(콘텐츠) **완전 분리**.
- **테제 수정**: 원래 "후기들이 쌓이는 것=서이추, 별도 글쓰기 없음"이었으나, **후기가 참여 허들이 돼 콜드스타트 활성화를 막는다**는 우려 → 서이추를 **글쓰기 게시판**으로 분리(블로그만 있으면 됨). 매소리 포스트잇 보드(후기=서이추) 모델 폐기.
- 스팸 방어: **블로그 등록 필수 + 레이트리밋 + 검증**(리뷰노트식 "맞이웃 홍수" 경계, 품질 모니터링).
- **신규**: 서이추 글 테이블 + 글쓰기/목록 API. **인스타 맞팔은 Phase 3**(블로그 먼저).

### 프로필 이미지 (신규)
- **직접 업로드**, **기본 이미지 제공**, **원하는 사람만 등록(선택)**. 저장소(blob) 없어 **배너처럼 data URI로 DB 저장**(용량 제한·리사이즈), `users.profile_image` 컬럼. 서이추/후기 작성자/MY 아바타 공통. 서이추 출시를 막지 않게 독립 작업.

### 런칭 쿠폰 이벤트 (콜드스타트 부트스트랩)
reciprocal(서이추)은 최소 풀 없으면 얇음 → **이벤트로 초기 후기 풀·활성 유저를 시딩**. 무협맵 쿠폰 이벤트 플레이북 있음([[project_launch_plan]]).
- **보상 = 후기 등록 랭킹**: 1등 3만 / 2등 2만 / 3등 1만원. (서이추 글은 이벤트 대상 제외 — 후기 등록만.)
- **가입 + 이메일 등록 필수** — 어뷰징 방지 + **이메일(웹/iOS 재방문 채널) 수집 드라이브**(일석이조).
- **성격 냉정히**: 랭킹×현금은 **소수 헤비유저/폭주 1등**을 굴림 → 이건 **"후기 콘텐츠 시딩" 이벤트**지 "서이추 참여 밀도" 이벤트가 아님(접었던 제보왕 랭킹과 같은 한계). **이벤트 후 참여 절벽** 가능 → 이후는 "블로그 키우기" 내적동기가 받쳐야(이벤트 후 유지율이 진짜 시험).

## Phase 구분 (다음 고도화)
> **이번 고도화 = Phase 1 = 하단 GNB 도입 + 그에 따라 추가되는 신규 화면**(설계서: Figma `Phase1` 페이지 9화면). 알림 실동작/웹푸시 = Phase 2, 커뮤니티 확장 = Phase 3.
>
> ⚠️ **Phase 범위 밖(제외)**: 이 기간 중 **유저 요청으로 상시 개선되는 것**(매장명·협찬내용 데이터 정정, 파서 보강, 소규모 UX·버그 수정 등)은 **Phase 계획에 넣지 않는다.** 별도 상시 유지보수이며 [[06-decision-log]]에 그때그때 기록. (Phase 1은 "새로 만드는 화면/구조"만 트래킹.)

### Phase 1 — GNB + 신규 화면 ← 이번 작업
**진행 순서: 1-A 먼저 완성·릴리스 → (검증 후) 1-B.** 1-B(커뮤니티)는 Phase 1에 포함되지만 **순서만 뒤로** — 별도 Phase로 분리하지 않음. 1-A는 1-B를 기다리지 않고 단독 출시 가능(구조 개편을 먼저 내보내 검증).

**1-A. 구조 + 내 장소(리텐션 코어)**
- [ ] 하단 **GNB 5탭 골격**(모바일) + 탭 라우팅 · **제보 탭 제거** · **신고=상세 컨텍스트 버튼화** · PC 아이콘레일 유지
- [ ] **홈** = 기존 지도 재배치 + 저장 핀 **앵커(항상 표시)** · **화면밖 방향표시**
- [ ] **내 장소**(신규): 목록 화면(집/회사/+), 카드=장소+"모집 중 N건" 배지, 카드탭→홈 지도 점프+주변 협찬
- [ ] **장소 추가/설정**: 검색(지명)+지도 롱프레스, 반경(km) 슬라이더, 카테고리 필터, 알림 토글(UI)
- [ ] **마이페이지**: 프로필·내 기여 통계(후기·좋아요)·설정 진입 *(내 후기 목록=커뮤니티로 이관, 내 제보=폐기, 2026-10-02)*
- [ ] **설정**: 알림 2레벨 UI(종류별 마스터)·계정·기타 *(알림 실발송은 Phase 2)*
- [ ] **메뉴**: 서비스 정보(소개·약관·개인정보·운영정책·문의·버전)
- [ ] (백엔드) **`push_prefs` 다건화**(이름 컬럼 + 집/회사 기본 + user/device당 다건) — 내 장소 저장/조회용

**1-B. 커뮤니티 + 공생** (상세 설계 2026-10-02 — 위 '커뮤니티' 절, [[06-decision-log]])
- [ ] **커뮤니티 골격**: 단일 메인 + 세그먼트 `[서이추][후기][내 후기]`
- [ ] **후기(세그먼트)**: 지도 등록 후기 최신순 피드(향후 지역 탭). '내 후기'=본인 필터
- [ ] **후기 등록(진입점 3개)**: ①기존 매장 상세 ②커뮤니티 '후기등록' 버튼 ③홈 검색핀 말풍선 — ②③은 **없는 매장 생성**(네이버 검색+주소 자동 지오코딩, 카테고리 자동분류)→블로그 URL 검증→등록
- [ ] **서이추(세그먼트)=글쓰기 게시판**: 프사·닉·시간·작성글·블로그, 블로그 등록자만 작성, 글 테이블+쓰기/목록 API (매소리 보드 모델 폐기)
- [ ] **프로필 이미지**: 직접 업로드·기본이미지·선택(`users.profile_image`, data URI) — 서이추 출시와 분리 가능
- [ ] **런칭 쿠폰 이벤트**: 후기 등록 랭킹(1등 3만/2등 2만/3등 1만) + 가입+이메일 필수 + "최근 마감→후기" 넛지
- 블로그 서이추 먼저(**인스타 맞팔은 Phase 3**)

### Phase 3 — 확장

## 측정 (효과 증명)
- 장소 저장률(방문자 중 ≥1개 저장 %)
- **장소 저장 유저 vs 미저장 유저 재방문율** ← 리텐션 증명 핵심
- 저장 → 알림 → 클릭 → 재방문 퍼널
- (선행) 어드민에 **재방문 지표 카드**(신규 vs 재방문 UV) 신설 검토 — 지금은 PV/UV만 보여 리텐션을 못 봄.

## 확정된 것 (이 스코핑에서)
- GNB 5탭 구성 + **제보하기 완전 제거** + **신고=컨텍스트 액션**.
- 내 장소 = 집/회사/+, 목록 화면, 반경·카테고리·알림(push_prefs 일반화).
- 후기 만료 후 등록 = 매장명 아카이브 검색([[06-decision-log]]).
- 알림 = 설정(종류별 마스터) / 내 장소(장소별) 2레벨.
- 마이페이지=나 / 메뉴=서비스정보 라우팅.
- 커뮤니티 = **단일 메인 + 세그먼트[서이추·후기·내후기]**. **서이추=글쓰기 게시판**(프사·닉·시간·글·블로그, 블로그 등록자만, 저허들 활성화) · **후기=지도 등록 후기 최신순 피드**(향후 지역 탭) · **후기등록 진입 3개**(없는 매장 생성·좌표/카테고리 자동) · **프로필 이미지 직접 업로드(선택)** · **블로그 서이추 먼저**(인스타 Phase3). (2026-10-02, [[06-decision-log]])
- 런칭 이벤트 = **후기 등록 랭킹**(1등 3만/2등 2만/3등 1만) · **가입+이메일 필수**.

## 열린 항목
- 탭 **네이밍**('내 장소' 계열 + 무협 테마 강도) — 보류.
- **이벤트 후기 카운트 규칙**(본인 블로그 검증 + 매장당 1개·중복 제외 + 기간 내 등록분), **top-3만 vs top-3+참가 추첨**(롱테일).
- **메뉴 5번째 탭 유지 vs 폐지**(정적 info만 남아 얇음 → 알림함/이벤트로 대체 검토) — 2단계에 재고.
- `push_prefs` **다건화 스키마**(이름 컬럼 + 집/회사 기본 + user/device당 여러 행; 현재 device_id 1행).
- **웹 푸시(FCM Web)** 도입 — 웹 다수 유저 알림 채널(알림 혜택 앱 한정 해소).
- 카테고리/반경 **설정 UI** 형태.
- 여행 **날짜** 도입 시점(2단계).
