# 지도 검색 고도화 백로그

> 실제 유저 검색 로그(`search_log` 510건 / `search_zero_log` 32건, 2026-11-17 분석) + 라이브 검증 기반. 검색은 핵심 기능(유저 사용량 많음)이라 데이터로 고도화 포인트를 우선순위화. **하나씩 착수**(원우씨 결정 ⓑ).
> 검색 흐름/우선순위는 [[frontend]] "지역+카테고리 검색"·`searchRegion`, 집계는 [[api-db]] `?visit=search`·[[admin]] 검색 카드.

## 데이터 요약 (2026-11-17)
- 검색 510건 중 **지역명 검색이 다수**(대전11·군자역7·제주7·광주6·계양구5…), 그 다음 **업종 키워드**(네일9·맞춤정장11[맞춤7+정장4]·웨딩5·피부과5·스튜디오5·왁싱3·단발펌3…).
- 0건율 ~6%(32건). 0건의 결은 ① IME 깨진 입력 ② 도로명/지명 ③ 네이버 미등록 매장명.

|---|---|---|---|
| 지역명(시/도/구) | 대전·계양구·혜화 | 지오코딩→지역 이동 | 정상 |
| 역명 | 군자역 | 랜드마크(POI 교통)→이동 | 정상 |

## 🔧 고도화 백로그 (우선순위)

### P1. IME 미완성 입력 정리 — 쉬움·효과 중 ⭐ (미착수)
"대구ㅜ"·"나주ㅏ주"·"ㅍ" 같은 **조합 중 깨진 검색어**가 0건의 ~1/3. 검색 실행 전 **끝의 단독 호환자모(U+3131–U+3163) 제거 + 완성형 글자 0개면 검색 스킵**. "대구ㅜ→대구"로 복구. 추가로 모바일 **IME 조합 중 enter/blur 발사 가드**.
- 손댈 곳: `searchRegion` 진입부(+`searchRegionMobile/PC` enter 핸들러), app.js. 집계(`?visit=search`)에도 정리된 term이 가도록.

### P2. 업종 키워드 사전 확장 — 쉬움·효과 큼 ⭐⭐ (미착수)
`SEARCH_CATEGORY_KEYWORDS`(app.js ~2892)에 **누락 업종** 많음. 실수요: **맞춤정장(11)·웨딩(5)·단발펌/펌(3)·꽃·애견·방어·회**.
- ⚠️ 카테고리 16종이라 일부는 딱 안 맞음("웨딩/애견/꽃"). **두 갈래 처리**:
  - ① 16종 매핑 가능분 → 사전 추가: **정장/맞춤정장→의류**, **펌/단발펌→헤어**.
  - ② 16종에 없는 업종/메뉴(웨딩·애견·꽃·방어·회) → **키워드 이름매칭**(지역 없이도 현재 지도에서 상호에 그 단어 포함 매장 필터 = `tryRegionNameKeyword`의 '지역없음' 확장) 또는 네이버 POI 노출.
- 주의: 카테고리 분류 원칙은 네이버 기준([[api-db]]) — 검색 사전 확장은 **표시/필터용**이지 매장 재분류와 무관.

### P3. 도로명/번화가 지명 검색 — 중간 (미착수)
"구리시 안골로"·"성안길"(청주 번화가)이 0건. **번호 없는 도로명은 NCP 지오코딩 약함.** → 도로명 패턴(로/길) 감지 시 네이버 지역검색을 주소모드로 태우거나, "번지를 붙여보세요" 안내.

### P4. 동(洞) 지역명 지오코딩 보강 — 낮음 (미착수)
혜화✅/면목❌ 불일치. `geocodeRegion`의 "서울 " 프리픽스 폴백이 서울만 커버 → **현재 지도 시/도를 프리픽스로** 붙여 비서울 동도 해결.

### P5. 매장명 오타/네이버 미등록 — 낮음 (미착수)
우미미코·로매기 등 네이버에도 0 → 근본 한계. 오타교정/부분매칭으로 일부만 건질 여지.

## 이미 반영됨 (참고)
- (2026-11-17) 동명 체인 picker에 **네이버 미등록 지점 병합 + "지역 붙여 검색" 힌트**(몽상 구로 케이스). [[frontend]] 검색 결과 리스트.
