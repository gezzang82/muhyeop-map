## 🔧 고도화 백로그 (우선순위)

### P1. IME 미완성 입력 정리 — 쉬움·효과 중 ⭐ (✅ 배포 2026-11-17, d2ea214)
"대구ㅜ"·"ㅍ" 같은 **조합 중 깨진 검색어**가 0건의 ~1/3. 검색 실행 전 **끝의 단독 호환자모(U+3130–U+318F) 제거 + 자모만이면 검색 스킵**. `cleanSearchQuery`를 `searchRegion` 진입부에 적용 → 정리된 term으로 검색·집계(`?visit=search`) 둘 다. 라이브 검증: 대구ㅜ→대구 이동·ㅍ→스킵.
- **남은 것(후속)**: 끝이 아닌 **중간 자모**("나주ㅏ주")는 미복구(드묾). 모바일 **IME 조합 중 enter/blur 발사 가드**(`isComposing`)는 미적용 — 재발 많으면 추가.

### P2. 업종 키워드 사전 확장 — 쉬움·효과 큼 ⭐⭐ (Part A ✅ 배포 2026-11-17 / Part B 보류)
`SEARCH_CATEGORY_KEYWORDS`(app.js ~2892)에 **누락 업종** 많았음. 실수요: **맞춤정장(11)·웨딩(5)·단발펌/펌(3)·꽃·애견·방어·회**.
- **Part A ✅ 완료**: 16종 매핑 가능분을 사전 추가 — **맞춤정장/정장/양복→의류**, **펌/파마→헤어**(단발펌='펌' includes 커버). "맞춤정장"→현재지도 '의류' 필터, "강남 맞춤정장"→강남 이동+의류 필터. 검증: detect 매핑 전수 + 기존(뷰티/사진관/운동) 회귀 없음.
- **Part A+ ✅ 보강(2026-11-20, 로그 재검증)**: 1,781건·0건 39건 재분석 결과 **마사지(3)·맞춤(6)·입술(2)** 이 **사전 누락 → 무반응 no-op**(토스트·이동·필터 전부 X, 라이브 Playwright 실측)였음 → **마사지·입술(반영구)→뷰티, 맞춤→의류** 추가(기존 '맞춤정장'만 걸려 '맞춤' 단독 미검출이던 것). 커밋 2892f5e. 웨딩·문신·굿즈·이사 등은 16종 밖이라 계속 보류.
- **Part B 보류(사유 기록)**: 16종에 안 맞는 키워드(웨딩·애견·꽃·방어·회)는 **현재 '전국 매칭 매장 picker 리스트'로 동작(안 깨짐)**. 이걸 "현재 지도 이름필터"로 바꾸면 **전국뷰에선 오히려 안 보이는 UX 트레이드오프**가 있어 보류. 바꾸려면 "현재뷰 필터 vs 전국 리스트" UX 결정 필요(실수요 웨딩5건이라 우선순위 낮음).
- 주의: 카테고리 분류 원칙은 네이버 기준([[api-db]]) — 검색 사전 확장은 **표시/필터용**이지 매장 재분류와 무관.

### P3. 도로명 검색 — 중간 (✅ 배포 2026-11-17)
"구리시 안골로"가 0건이던 원인: **번지 없는 도로명은 NCP 지오코딩이 실패**(실측 "구리시 안골로"❌ / "구리시 안골로 10"✅). → `geocodeRegion`이 **로/길로 끝나는 쿼리는 geocode 실패 시 ' 1'을 붙여 재시도**(원본→'서울 '원본→원본+' 1'→'서울 '원본+' 1') → 그 도로 시작점(안골로 1=37.597,127.131)으로 이동. 라이브 검증: 구리시 안골로→이동, 성수동/강남구 회귀 없음.
- **참고**: '거리/가'로 끝나는 상권(으능정이거리·성안길)은 번지형이 아니라 ' 1'로 안 됨 → 네이버 지역검색(POI) 폴백이 담당(성안길=POI 5건). 이건 POI 응답 변동에 의존(유저가 0 받은 건 그 변동).

### P4. 동(洞) 지역명 지오코딩 보강 — 낮음 (미착수)
혜화✅/면목❌ 불일치. `geocodeRegion`의 "서울 " 프리픽스 폴백이 서울만 커버 → **현재 지도 시/도를 프리픽스로** 붙여 비서울 동도 해결.

### P5. 매장명 오타/네이버 미등록 — 낮음 (미착수)
우미미코·로매기 등 네이버에도 0 → 근본 한계. 오타교정/부분매칭으로 일부만 건질 여지.
