# 데이터 수집·자동등록 운영 가이드 (오토파일럿)

> **한 줄**: 협찬 플랫폼(디너의여왕) 캠페인을 **자동 수집 → AI 검증 → 지도 자동등록**하고, 애매한 것만 사람이 검수하는 **거의 무인 운영** 체제. (2026-08 가동)
>
> 이 문서는 **업무/운영 관점**의 안내다. 코드 상세는 `docs/admin.md`·`docs/api-db.md`, 파이프라인 스펙은 [03-platform-analysis](03-platform-analysis.md) 8절, AI는 [13-ai-automation](13-ai-automation.md), 결정 이력은 [06-decision-log](06-decision-log.md).

---

## 1. 데이터 흐름

```
[수집] 플랫폼에서 신규 캠페인 긁기
   ↓
scraped_items (승인 대기 큐)
   ↓
[AI 검증 = 오토파일럿] 3갈래 자동 분류
   ├─ 🟢 자동등록 → 매장·캠페인 생성 → 즉시 지도 공개
   ├─ 🟡 검수 대기 → 운영자가 어드민에서 확인 (애매한 것만)
   └─ 🔴 스킵 → 버림 (마감 지남 등)
```

- **검증 시점**: 수집 직후 자동. 별도 트리거 없음.
- **공개 시점**: 자동등록되는 **즉시** 지도(muhyeop.com)에 반영. "올리기" 버튼 없음.

---

## 2. 두 가지 실행 경로

| | Vercel 크론 (자동) | 로컬 크롤러 (수동) |
|---|---|---|
| 실행 | 매일 06:00 KST 자동 | `scripts/크롤러-시작.command` 더블클릭 |
| 플랫폼 | 디너의여왕(서울) | 디너의여왕·강남맛집·링블·포블로그·서울오빠 |
| 지역 | 서울 | 전국(디너의여왕 지역순회 + 나머지 전국 피드) |
| 컴퓨터 | 꺼져 있어도 돎 | 켜둔 동안만 |
| 처리량 | 하루 1회·300초(~100건 천장) | 무제한 (켜둔 만큼) |
| 검증 | 실행 시 1회 | **지역별 수집 직후 즉시** |
| 멈춤 | — | 창에서 Control+C |

- **평소**: Vercel 크론만으로 서울은 자동 유지. 운영자 할 일 없음.
- **밀린 물량/타지역 빨리 채우기**: 컴퓨터 켠 김에 로컬 크롤러 더블클릭 → 몇 시간이면 4개 지역 소진.
- 크론과 로컬 크롤러를 **동시에 돌려도 안전**(커서·중복방지로 충돌/중복 없음).

---

## 3. 운영자가 하는 일 (거의 없음)

1. **평소**: 아무것도 안 해도 됨.
2. **빨리 채우고 싶을 때**: `크롤러-시작.command` 더블클릭 (끌 땐 Control+C).
3. **검수**: 어드민 → 매장/캠페인 등록 → 데이터 수집 → **승인 대기**의 🟡 소수만. 각 행 `검수` 열의 사유(`auto_note`) 보고 [승인]/[수정]/[반려].
4. **AI 등록분 확인/회수**: 어드민 조회 → 캠페인 → 출처 **AI** 필터. 문제 있으면 해당 행에서 숨김/삭제.

---

## 4. AI가 자동으로 판정하는 기준

- **기본 승인** — 플랫폼에서 온 정상 데이터라 전제. 협찬 내용이 짧거나 홍보성인 건 정상(반려 안 함).
- **반려(검수로)는 명확한 문제만**: 스팸/의미없는 매장명, 배송형/무매장, **같은 위치(300m)의 진짜 중복**.
- **카테고리 교정**, 요일·카테고리 불확실은 자동등록 막지 않음(요일은 비워서 등록).
- **오등록 방지 페일세이프**: AI 호출 실패·저신뢰면 자동등록 안 하고 검수큐로.

---

## 5. 안전장치 (중복·오등록 방지)

- **중복 매장 방지**: 같은 이름+좌표면 매장 재사용(채널별 캠페인만 추가). 승인은 순차 실행(동시 등록 경합 차단).
- **중복 캠페인 방지**: 같은 링크(플랫폼 캠페인 URL은 고유)면 재등록 안 함.
- **최초 제보자**: 수집·자동등록분은 **비움**(특정 개인의 제보가 아니므로). 실제 유저가 앱에서 한 제보는 보존.
- **개인정보(PII)**: 이메일 등은 로그인 유저만, 공개 응답에서 제거.

## 6. 비용

- **OpenAI(GPT, gpt-4o-mini)**: 신규매장 후보에만 호출. **주당 약 14원**(호출당 ~540토큰). 월 몇백 원 수준.

## 7. 범위·한계·확장

- **플랫폼(2026-08 확장)**: 디너의여왕 외 **강남맛집·링블·포블로그·서울오빠**까지 `api/_scrape.js`에 파서 추가돼 가동 중(방문형 위주). 각 파서만 다르고 오토파일럿·중복방지·지오코딩·검수큐 인프라는 공용. 추가는 [03-platform-analysis](03-platform-analysis.md)(robots·ToS 확인 필수).

- **처리량 한계**: Vercel 크론 1회는 상세 fetch 속도상 ~150건이 천장. 전량/실시간은 **로컬 크롤러** 또는 **Vercel Pro(하루 여러 번)**.

## 8. 주의 (운영 사고 방지)

- **`.env.local`에 `vercel env pull` 쓰지 말 것** — Vercel의 민감(Sensitive) 변수는 **빈 값으로 내려와** 기존 로컬 키까지 전멸함(2026-08-30 재발). → **보호 훅 도입**: `.claude/hooks/protect-env-local.sh`(PreToolUse, `settings.local.json`에 등록)가 `.env.local`에 대한 Edit/Write·`sed -i`·리다이렉트·`tee`·`cp/mv/rm`·`vercel env pull`을 **자동 차단**(읽기는 허용). 값 수정이 필요하면 훅을 잠시 해제하고 진행. (기존 `.env.local.backup` 안전망은 이 훅으로 대체·삭제)
- **Sensitive 키는 로컬에 못 pull됨** — KAKAO/NAVER OAuth·`ADMIN_PASSWORD`·`SESSION_SECRET` 등은 Vercel 프로덕션에만 있고 복호화 불가. 로컬에 필요하면 각 콘솔에서 직접 복사해 넣어야 함(`SESSION_SECRET`은 로컬 전용 랜덤값도 가능, 단 프로덕션 세션과 비호환).
- **지도 지오코딩 키**(`NAVER_MAPS_KEY_ID`/`NAVER_MAPS_KEY`)는 **Vercel 환경변수에도 등록**해야 크론/서버 자동등록이 정확 좌표를 얻음.
- **Vercel 키와 로컬 키는 별개 관리** — 한쪽이 죽으면(401) 그쪽 실행은 자동등록 못 하고 검수로만 감.
