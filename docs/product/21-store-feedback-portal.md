# 리뷰어 체험단 피드백 + 점주 포털 (스코핑)

> **상태: 논의·기록만 (2026-11-17). 지금 당장 구현 X.** 리스크·설계 방향이 정리돼 나중에 착수할 때 바로 이어가기 위한 문서.
> 관련: [[04-revenue-model]]·[[08-partnership]]·[[20-reviewer-data-platform]]·[[19-community-activation]]·[[07-legal-review]]·[[06-decision-log]](2026-11-17)

## 한 줄 요약
후기 등록 시 리뷰어가 그 가게 체험단을 **추천/비추 + 사유(태그)** 로 평가 → **긍정 집계만 공개**, **부정은 비공개**, 그리고 **가게 점주가 무협맵에 가입(소유 인증)하면 자기 가게 피드백을 익명 집계로 열람**. 부정 데이터를 "저격"이 아니라 **점주 개선 코칭 + B2B 획득 훅**으로 전환하는 설계.

> **⚠️ 더 큰 그림(2026-11-17, 원우씨)**: 점주를 무협맵에 끌어오는 **진짜 메인 훅은 "재고 떨이(마감 할인 판매)"** 다 — 아래 [재고 떨이] 섹션. 피드백 열람은 곁다리 혜택이 되고, 재고 떨이가 점주 가입의 실익(돈 버는 이유)이 된다.

## 🎯 엔드게임 — 리뷰어↔점주 직거래 플랫폼 (체험단 탈중개화)
(2026-11-17, 원우씨) 위 피드백·재고 떨이로 점주를 온보딩시키면, 궁극적으로 **리뷰어와 점주가 직접 거래하는 서비스**가 된다.
- **현재**: 체험단 플랫폼(리뷰노트·디너의여왕…)이 중간에서 점주 돈 받고 리뷰어 매칭. 무협맵=그걸 지도로 모으는 **aggregator(안내자)**.
- **엔드게임**: 점주가 무협맵에 **직접 체험단 등록** → 리뷰어가 **직접 신청** → 무협맵이 **매칭·검증·신뢰**로 중개 = **직거래 레일**(중간 플랫폼 탈중개화).
- **왜 무협맵이 할 자격(해자)**: 직거래의 진짜 난관은 "이 리뷰어 믿을 만해? 이 가게 대우 괜찮아?"=**신뢰**. 무협맵은 **리뷰어 신뢰 데이터([[20]] 블로그 이력·프로필·등급) + 점주 피드백(이 문서) 양쪽을 다 가진 유일한 위치**. 양쪽이 한 지도에 모여 있고 동네 기반이라 로컬 매칭 최적.
- **핵심 통찰 = 재고 떨이·피드백은 "목적"이 아니라 "다리"**: 재고 떨이=점주를 돈 실익으로 온보딩하는 **트로이목마**, 피드백=머물게 하는 고리 → 들어온 점주에게 "체험단도 직접 올려보세요"로 직거래 확장.
- **순서(이미 맞게 깔림)**: ①리뷰어 신뢰 데이터([[20]], 지금=블로그 불러오기) → ②재고 떨이·피드백으로 점주 온보딩(이 문서) → ③점주↔리뷰어 접점 → ④**직접 체험단 중개(엔드게임)**.
- **⚠️ 가장 어려운 길**: 직거래=양면시장 끝판왕(매칭·검증·**분쟁[노쇼·갑질·저품질후기·환불] 책임**을 무협맵이 떠안음) / 기존 플랫폼이 공존→**경쟁자 전환**(크롤링 차단·견제) / 수익모델 광고·제휴→**거래 수수료**로 전환(다른 사업) / **밀도 문제**(동네 단위로 양쪽 채워야 작동, 현 규모론 이름). → **"지금 당장"이 아니라 순서대로 쌓기**가 정답.

## 🥖 점주가 가입할 진짜 이유 = 재고 떨이 (마감 할인 지도 판매)
**아이디어(원우씨)**: 빵집처럼 **당일 소진해야 할 재고**를 점주가 저렴하게 등록 → 무협맵 회원이 **지도에서 "근처 마감 할인"을 보고 찾아가 현장 구매**. 무협맵은 **연결만**(당근 스타일).
- **뭐랑 같나**: "Too Good To Go / 라스트오더"를 **무협맵 지도 위에** 얹는 것. 무협맵은 이미 **지도·회원·가게 핀·카테고리 필터**를 보유 → 재고 떨이가 **마감 핀으로 자연 중첩**(자산 재활용).
- **왜 빵집 wedge**: 당일 소진 압박 큼·잉여 매일 예측 가능·할인 여력(마진) 있음·동네 밀착("지도 보고 찾아가기"와 궁합 최고). 한 카테고리×한 동네 PoC로 시작.
- **점주 가입 이유 2단**: ①**재고 떨이 판매**(돈 버는 실익=메인 훅) + ②체험단 피드백 열람(곁다리). → 가입 동기가 확실해짐 = 이 문서 전체(점주 포털)의 추진력.

### 큰 결정 포인트
1. **타깃 충돌/확장**: 현 유저=체험단 리뷰어(공짜 협찬), 재고 떨이 구매자=가성비 동네 소비자. **겹치나 완전 같진 않음** → 유저 베이스 확장(good) vs 체험단 코어 정체성 희석(risk). **가장 큰 결정.**
2. **거래 깊이(MVP 핵심)**: ⓐ**전시형**(등록→지도 핀→현장 구매, 결제·정산 없음) vs ⓑ**인앱 결제·예약**(PG·정산·노쇼, 복잡·규제). → **1인 운영이면 ⓐ로 시작**(지도 위 게시판, 검증부터).
3. **닭-달걀(양면시장)**: 빵집 몇 곳 직접 섭외로 공급 깔고 → 기존 회원에 "근처 마감빵" 푸시로 수요. 좁은 동네 하나로.
4. **점주 참여 마찰**: 재고 떨이는 **매일 능동 등록**(체험단 크롤링과 다름) → 원탭 등록·반복 템플릿으로 마찰 최소화가 성패.

### 리스크
- **정체성 희석**: "체험단도 되고 마감할인도 되고"는 뾰족함을 흐릴 수 있음 → 같은 자산(지도·가게·회원) 공유하되 **별도 레이어/탭** + "리뷰어 + 동네 가성비"를 **한 생태계로 묶는 서사** 필요.
- **경쟁**: 라스트오더·당근 인접. 차별점 = **체험단으로 이미 확보한 가게·리뷰어 네트워크 위에 얹는다**(무에서 시작 아님).

### 왜 지도가 정답인가 — "검색"이 아니라 "발견"(2026-11-17, 원우씨)
- **검색(네이버·배민)**: 의도가 먼저 있어야 작동("빵집 어디?") → 이미 있는 수요만 가져감. **아무도 "마감 할인 빵"을 검색하지 않음.**
- **지도(무협맵)**: 의도 없이도 "어? 내 주변에 이게 있네"를 만듦 → **없던 수요 창출(latent→충동구매)**. 마감 할인은 **검색으론 안 팔리고 발견으로만 팔림** → 지도가 유일한 판로.
- **"퇴근길" = 위치 × 시간 트리거(이미 가진 재료)**: 내 장소(집/회사, [[17-travel-pins]])로 **퇴근 동선**을 알고, 위치 기반 푸시([[16-push-notifications]])로 **"지금 네 퇴근길 ○○빵집 마감 30%"** 를 그 시간·그 위치에 쏨 → 앱 안 켜도 발견이 날아오는 재방문·거래 트리거.
- **같은 지도 primitive, 두 발견**: 리뷰어="내 주변 체험단"(지금) / 소비자="내 주변 마감 할인"(엔드게임). 지도를 코어로 잡은 게 이 확장 전체의 전제조건(우연 아님).

### 위치/단계
- **로드맵 Phase 3(제휴·수익화)** 영역. 점주 포털(소유 인증·가입)이 선행 인프라 → 그 위에 재고 떨이.
- **MVP 추천**: 전시형(결제X)·빵집 1카테고리·1동네 PoC → 되면 확장.

## 왜 (가치)
- 리뷰어 관점의 **"이 가게 체험단 할 만한가?"** 신호는 어느 체험단 플랫폼에도 없음(독점 데이터·해자). 수다방에서 나온 실제 페인("사장님 앞에서 체험단이라 말하기 어색/대우 별로/제공가 vs 메뉴가")이 전부 가게별 체험단 경험 품질.
- 리뷰어: 신청 전에 "여기 할 만한지" 판단 → 무협맵이 "모집 목록"을 넘어 **가게 평판 레이어**로.
- 점주: 지금 무협맵에 가입할 이유 0 → **"리뷰어가 내 체험단을 어떻게 느꼈는지 보려면 가입"** = 강력한 B2B 획득 훅 → 제휴·광고의 입구.
- 포지셔닝 역전: "가게 깎는 앱" → **"가게가 체험단 운영을 개선하게 돕는 파트너"**(제휴 영업 명분). 양면 네트워크([[20]] 비전과 정렬).

## ⚠️ 부정 공개가 왜 위험한가 (공개 안 하기로 한 근거)
부정의 **이득은 리뷰어 한쪽에만, 손해는 법·수익·공급·운영 네 방향**에 걸리는 비대칭 구조라 **초기 공개 금지**.
1. **법적(가장 약한 고리)**: 한국은 **사실적시 명예훼손도 처벌**(정보통신망법). 결정적으로 **가게는 무협맵 리스팅에 동의한 적 없음**(크롤링 등재) → "동의 없이 평판 훼손" 클레임이 정당성을 가짐([[07-legal-review]] 크롤링 이슈와 겹쳐 가중). 권리침해 삭제요청 임시조치 의무 → 1인 운영 감당 불가.
2. **수익모델 자살골**: 돈 방향이 가게·플랫폼 제휴([[04]]·[[08]])인데 "가게 깎는 앱"이면 제휴 문전박대. 플랫폼도 크롤링 차단 명분.
3. **생태계 자해**: 콘텐츠 원천=가게가 올리는 체험단 캠페인. 부정 노출이 무서워 가게가 체험단을 꺼리면 **공급 자체가 말라** 보여줄 게 없어짐.
4. **신뢰성·억울함**: 초기 표본 1~3개 → "비추 1명"이 "비추 100%"로. 체험단 리뷰어 인센티브 편향("제공 많이 받고 싶음"→"제공 빈약" 과대). 떨어진 리뷰어·경쟁 가게 어뷰징 검증 불가.
5. **문화**: "리뷰어가 가게 뒷담화하는 곳"이 되면 가게가 리뷰어 자체를 경계 → 리뷰어 생태계도 역풍.

## 설계 방향 (합의)
- **공개(가게 상세) = 긍정 집계만** — 👍 태그·추천도(%)만. "긍정이 적은 가게"는 리뷰어가 알아서 역산 → 부정 안 띄워도 신호 전달됨.
- **부정·비추·사유 = 비공개 수집** — 공개 화면엔 안 띄움.
- **점주 포털(핵심 아이디어)** — 점주가 **소유 인증** 후 가입하면 **자기 가게의 부정 포함 피드백을 익명 집계로** 열람. 본인에게만 보이므로 제3자 공개 아님 → 법적·평판 리스크 거의 소거.
- **사유는 자유서술 대신 태그(칩)** — 명예훼손↓·집계 가능·입력부담↓·비속어 검수 불필요. 자유서술은 넣는다면 **선택·비공개**(점주/운영자만, 가게 상세 미노출).

### 제안 태그(초안, 리뷰어 실제 페인 기반)
- 👍 추천: 사장님 친절 / 제공 넉넉 / 체험단 눈치 안 보임 / 예약·응대 편함 / 사진 찍기 좋음 / 또 신청하고 싶음
- 👎 비추: 제공 빈약 / 체험단 눈치 보임 / 추가결제 유도 / 예약·응대 까다로움 / 재방문 의향 없음

## 점주 포털 — 반드시 깔려야 할 전제 2개
1. **가게 소유 인증** (남의 가게 피드백 열람 차단=또 다른 사찰 방지). 난이도: 대표번호 인증코드(가벼움) / 사업자등록번호+운영자 수동승인(중간) / 네이버 플레이스 소유주 연동(무거움). **MVP는 대표번호 인증 or 수동승인 권장.**
2. **리뷰어 익명·비식별** (점주의 색출→보복 방지=리뷰어 신뢰의 생명줄): 개별 후기 아님·**익명 집계만**, **최소 표본 게이트**(예: 5명+ 넘어야 조회, 안 그러면 "최근 체험단 1명"=범인 특정), 작성자·날짜·특정 가능한 디테일 제거, 톤은 "개선 인사이트"(날것 "비추 60%"보다 "아쉬워한 점 top3").

## 단계 (phasing)
- **Phase 1 (리스크 0, 먼저)**: 리뷰어가 추천/비추 + 사유태그 남김 → **전부 비공개 수집**. 공개엔 긍정 집계만. 점주 기능 없이 **데이터부터 축적**(공개 안 하니 리스크 없음). 데이터가 먼저 쌓여야 Phase 2가 "보여줄 게 있는" 상태로 출발(점주 포털 먼저 만들면 빈 깡통).
- **Phase 2 (점주 포털 = B2B 입구)**: 점주 가입 + 소유 인증 → 자기 가게 익명 집계 피드백 조회. 제휴·수익의 실질적 첫 다리.
- **(나중)**: 상세 리포트·리뷰어 응대 기능을 프리미엄 유료화 경로.

## 열린 결정 (착수 시 정할 것)
1. 소유 인증 방식: 대표번호 인증 / 사업자+수동승인 / (나중)네이버 연동
2. 점주 열람 범위: 익명 집계만(권장) vs 개별 코멘트(위험)
3. 무료 vs 유료: 점주 포털을 가입유인(무료)으로 열고 나중 프리미엄(권장)
4. 커버리지: 자동수집(blogimport) 후기엔 sentiment 비어 있음 → 수동 등록·블로그 불러오기 확정 단계에서 **선택 입력**, 쌓이는 만큼 신호 강화
5. 태그 세트 최종 확정(위 초안 가감)

## 데이터 모델 스케치 (참고, 미구현)
